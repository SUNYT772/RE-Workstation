# 跨版本符号迁移：原理与证据

来源：skills/binary-diff/SKILL.md

## 适用范围与概念

适用情境是旧版有符号/逆向结果、新版符号缺失：内核和驱动缺 PDB、应用更新后迁移函数名或新偏移、保护机制更新后重新定位已知函数。两个完全无关的二进制首先存在“是否同源”的问题，不能直接假设函数对应。BinDiff、Diaphora 是原文的传统图/结构差分背景，LLM 是语义辅助解释背景，不是本模块依赖。

### 与相邻领域的分工

从零理解一个二进制、已有知识跨版本迁移、两个程序结构差分和安全补丁根因定位具有不同目标。符号迁移主要回答“新版哪条引用或哪个实体对应旧名”，不自动回答漏洞是否可利用。

### 原成本比较的适用性

原记录比较了人工双视图、传统自动匹配、完整 agent 工作与单函数结构化比对。原示例称 200 函数约 1 元、约 10 秒/函数，完整 agent 约 50–100 元；这些只是当时样本与模型环境的未独立验证估计，不能作为当前价格、速度或准确率承诺。实质经验是限定输入范围、缓存与结构化结果能减少重复解释成本。

## 核心原理与技术细节

### 对应关系的输入

同一候选锚点在两版中分别有反汇编和伪代码：旧版文本包含可信名称，新版文本提供真实指令、地址和结构。目标符号列表限定迁移范围。高层语义、常量、字符串与调用结构共同支撑对应，地址数值本身常因重排而变化。

明确的输入字段和输出类型有助于复核对应关系。可交换 YAML 记录这些关系，数据库名称和注释是其展示形式。

### 锚点选择策略

| 锚点类型 | 原可靠性判断 | 判断依据与限制 |
| --- | --- | --- |
| 导出函数 | 最高 | 名字可能稳定而地址改变，仍需核对实现身份 |
| 字符串引用 | 高 | 文本可保持不变，引用位置可能迁移 |
| 常量/魔数 | 中 | 特征值可能稳定，也可能多处出现 |
| 代码模式 | 中 | 结构相似可形成候选，但代码地址可能全变 |

锚点错误会传播到内部调用与后续迁移，因而“结构相似”与“已确认同一函数”需要区分。

### 完整流程的知识关系

数据准备确定两版身份和符号可信度；候选锚点把范围限制到一组对应函数；反汇编/伪代码展示局部关系；输出记录指出新版引用、名称和偏移；验证过的对应可作为其他函数的锚点。迭代扩展只在前一层对应可靠时增加信息，而不是把第一轮推断自动升级为事实。

### 批量处理与上下文规模

原批量建议以单函数为边界，避免整份二进制上下文挤压证据。原 `<200` 行、`>500` 行和 `>1000` 行是中小、大型与极大函数的经验分组，不是语义正确性的阈值。拆分时要保留相关调用、局部定义和分支上下文；缓存能够避免同一输入反复解释。

原 10–20 并发与模型切换属于执行编排，不作为要求。保留的技术目标是吞吐、上下文完整性、结果一致性和可追溯缓存之间的平衡。

### YAML 输出的五种符号类型

| 类型 | 语义 | 关键字段与定位条件 |
| --- | --- | --- |
| found_vcall | 虚调用或虚函数指针读取 | insn_va、insn_disasm、vfunc_offset、func_name；位置是含位移的指令 |
| found_call | 直接普通函数调用 | insn_va、insn_disasm、func_name；名称对应调用目标 |
| found_funcptr | 非虚普通函数指针引用 | insn_va、insn_disasm、funcptr_name；位置确实装载或引用目标地址 |
| found_gv | 全局变量引用 | insn_va、insn_disasm、gv_name；引用指令与变量实体分开 |
| found_struct_offset | 普通结构体成员访问 | insn_va、insn_disasm、offset、size、struct_name、member_name |

虚表偏移归 found_vcall，不与普通成员偏移混合。字节宽度 size、位移 offset 和指令地址 insn_va 表示不同量。没有证据的目标可以保留为空，不应补入无关符号。

### 解析后的知识应用语义

直接调用的名称属于 call target，函数指针名称属于 funcptr target，全局变量名属于实际变量地址；虚调用和成员偏移则可作为引用点注释。引用指令地址不能直接当作所有目标实体的地址。完整字段示例见 [符号对应记录格式](references/prompt-template.md)。

## 观察项与判断依据

### ntoskrnl 缺 PDB 场景

原例使用 10.0.26100.2000 的有符号记录与 10.0.26100.2605 的无符号记录。共同导出 `PsSetCreateProcessNotifyRoutine` 是候选锚点；旧版内部调用名 `PspSetCreateProcessNotifyRoutine` 与新版 `sub_140822108` 的对应由调用语义解释。

这些版本与地址只是原场景，不证明当前 PDB 是否被下架，也不提供可通用套用的实际偏移。报告中应把“原例中的符号对应”与“特定文件已验证对应”明确区分。

### 应用更新场景

原 v1.0 到 v1.1、200 多个已命名函数的场景体现知识复用：导出或字符串建立锚点，函数内部调用扩大候选集合。原名称可信度、版本差距、编译优化和关键位置抽检决定迁移结果的可信程度。

## 故障定位与经验

最常见风险是锚点错配、超大上下文遗漏、相关符号混淆和不经验证的批量命名。关键符号需要在新版真实指令与引用关系中核对。原模型选择表将 DeepSeek V3、GPT-4o、Claude Sonnet、Claude Opus 分为中小、复杂和极复杂上下文的历史选项；本页仅保留名称背景和“规模、推理难度、成本、速度是不同维度”的判断，不给出当下模型推荐或 API 配置。

## 证据与报告结构

记录两版文件身份、符号来源、锚点依据、两版代码范围、目标符号清单、新版引用与目标实体、结构偏移和宽度、对应的验证状态、未匹配项及误差边界。缓存条目应能对应其输入版本与范围；名称迁移不能抹掉不确定性。
