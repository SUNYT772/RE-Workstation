# Agent 工作流理解、状态与验证的知识

来源：skills/llm-security/references/agent-obedience-engineering.md

## 原材料语境

源材料讨论 AI 编码 Agent 读完 README / RULES 后只确认、跳过内容或产生语义错误的现象，引用 Anthropic Skill Engineering、Microsoft Code Words、Strands Steering Hooks、Gradient Flow Harness Engineering 等 2026 年背景。本页把八项工程思路、十类失败、五种结构和三类模板改写为技术知识；不保留强迫 Agent 执行、安装、全局注入或跨任务限制。

## 核心问题诊断

| 原根因 | 机制解释 | 可观察证据 |
|---|---|---|
| 上下文注意力衰减 | 长上下文中不同位置被利用的程度不同 | 相同要求放置位置变化时的遗漏差异 |
| 语义覆盖 | 模型重解释要求，导致目标与输出不一致 | 用户原意、模型解释和交付物之间的差异 |
| 建议与要求混淆 | 条件、可选项和必要条件表达不清 | 对条件成立与否的不同处理 |
| 缺少状态核验 | 仅自然语言叙述不能证明状态转换发生 | 声称完成但缺少对应产物/状态 |
| 静默状态腐化 | 格式正确但语义错误持续累积 | 中间产物与真实业务约束不一致 |

这些是原文解释模型，不意味着能由单次失败诊断底层注意力机制。

## 技术 1：Critical-First Pattern

信息层级与上下文位置影响发现成本。原对比把重要目标埋在七十行背景后，与先展示当前目标和完成证据作比较。其可迁移知识是目的、必要前提与背景分层，而不是把“立即执行”放到每个文件。渐进披露使概览负责判断相关性，细节在具体问题出现时可被读取；安装、路由和全局规则注入模板已转为这种布局原理。

## 技术 2：Directive Over Suggestive 的语义层次

RFC 2119 的 MUST / MUST NOT / SHOULD / MAY 分别描述必要、禁止、偏好和可选，但词强度不等于真实授权或完成事实。源表以尝试、下一步、建议读取、缺少能力、记录经验、一般“应该”六类表达比较歧义。知识用途是让文档区分技术不变量、建议与可选信息；本页不把这些词转为限制 Agent 的协议。

## 技术 3：借口反驳表所暴露的十类失效

| 原文失败叙述 | 技术问题 | 可复核依据 |
|---|---|---|
| 某一步可直接省略 | 依赖与实际需求混淆 | 前提是否被替代证据满足 |
| 自认不必进行某项 | 判断标准未显式说明 | 标准与具体任务约束的对应 |
| 替用户推断不需要 | 交付范围被擅自缩减 | 用户范围与实际产物差异 |
| 已经知道而不看材料 | 通用经验覆盖局部信息 | 材料中的环境特有条件 |
| 为节约时间跳过 | 并行与依赖被混同 | 两项工作是否共享状态或有先后依赖 |
| 记得工具旧路径 | 环境位置随机器变化 | 当前环境的实际位置证据 |
| 基本完成便结束 | 完成定义与结果不一致 | 交付物是否满足本次需求 |
| 缺少索引便猜测 | 缺少证据被错误填补 | 缺失项与不确定性是否明确 |
| 未明确提报告便省去 | 默认产物与用户意图混同 | 本次约定的交付形式 |
| 简单问题不记经验 | 失败信息无法迁移 | 问题、原因、修复与验证是否保留 |

源表中的强制反驳和“唯一完成定义”已改为失效原因与证据，不创建新的用户审批或固定 checklist。

## 技术 4：五种 Skill 工程模式

| 模式 | 原文适用问题 | 可保留的知识结构 |
|---|---|---|
| Linear Flow | 顺序依赖明确 | 输入、状态转换、输出和失败条件 |
| Decision Tree | 平台导航与诊断 | 分支判断依据和相关参考 |
| Iterative Loop | 检查/修复循环 | 结果反馈和差异定位 |
| Baton Loop | 跨会话协作 | 外化当前状态、已完成事实与剩余问题 |
| Multi-Phase + Checkpoints | 长周期复杂工作 | 中间产物、影响判断与检查点 |

原项目的十五步行为链、三维路由矩阵、逐项打勾和 journal 接力，分别是这些模式的历史应用，不能由此推导其他 Agent 也需要固定十五步。

## 技术 5：In-Band 验证与 Steering Hooks

自我核对可使输出声明与实际产物比较，源例关注遗漏、路径、完成状态和可复现证据。它的局限是审查者与执行者可能共享误解，自述也不替代状态检查。技术目标是区分已阅读、已尝试、已产生结果、已验证四种状态，而不是嵌入不允许结束的提示。

## 技术 6：Code Words 与精确参数

源材料比较语义参数（如结果数量）与不透明标识符映射，称遵循率从 68.4% 到 100%。此数字属于源研究的特定设置，不保证跨系统。知识在于语义化字段可能诱发重新解释，不透明枚举减少自由解释空间，但映射必须明确、可追溯。保留类型、枚举、映射和实际值的一致性，不复制调用参数或安装配置。

## 技术 7：Dual Validation

独立产物检查与执行过程可以使用不同视角：结果与需求比较、具体差异和引用支持修正。原双 AI 回路表达生产、审查、反馈、修正，不规定多代理、消息发送或强制子任务。自审查也可能共享盲区，报告应区分验证证据与验证者身份。

## 技术 8：上下文窗口布局

原图把首尾各 10% 与中部 80% 作概念性注意力布局，首部放目的，中部放详细参考，末尾放核对内容。它是布局经验，不是所有模型的定量分布。可迁移目标是让读者快速识别相关性、技术前提和结果定义，同时避免把所有细节挤进入口。

## 三类 Prompt 模板承载的技术目标

### 模板 A：启动上下文

源模板混合包根位置、全局配置、领域路由、能力状态与实际任务。知识化后分别对应材料来源、环境特征、相关领域与预期交付。全局注入、安装和立即调用语句已移除，不作为本页行为要求。

### 模板 B：子模块入口

源模板关注范围、环境能力、缺失条件和不确定问题。可迁移内容是模块用途、输入前提、可用证据与缺失信息表达，入口无需约束读取者进入固定动作阶段。

### 模板 C：完成声明

源模板涉及实际结果、路径证据、重现材料、经验和报告。知识目标是声明与证据一致，而非把固定清单当成所有任务唯一终止条件。

## 行为失效与知识排版结论

只说理解、把阅读当执行、用记忆代替当前状态以及未经证据支持就声称完成，是原文列举的四种可观察失配。原结尾强调强指令和反驳表，本版保留其试图解决的发现成本、状态歧义和验证缺失问题，采用目标清晰、技术层次完整、证据可追溯的知识排版。
