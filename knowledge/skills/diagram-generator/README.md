# 图表与关系表达

把自然语言、笔记、代码关系、表结构或已有图稿整理成可编辑图表。图表表达的是实体、关系、边界、状态、时间和不确定信息。

## 图形选择

| 问题 | 图形与可选记法 |
| --- | --- |
| 流程、分支、职责 | 流程图、泳道，Mermaid flowchart |
| 交互次序、并发、重试 | 时序图，Mermaid / PlantUML |
| 生命周期、状态迁移 | 状态图，stateDiagram / UML state |
| 数据模型 | ER 图，实体、键、基数 |
| 类、接口、对象 | 类图，重要字段与关系 |
| 项目时间 | Gantt |
| 层次与想法 | Mind map |
| 用户历程 | Journey |
| 版本分支关系 | Git graph |
| 大规模依赖与网络 | DOT，有向/无向图与 cluster |
| 系统架构 | 分层 flowchart、DOT cluster、UML component/C4 风格 |
| 带权流量 | Sankey，注明记法兼容性 |
| 自定义精确布局 | SVG，保留标题和文字语义 |

## 信息与排版

先辨认实体和边的语义，再组织空间。短标签、统一大小写、稳定的 ASCII 标识、清晰边界可以减少歧义。过程图说明正常路径、分支、失败、重试、人工节点；架构图区分客户端、服务、数据、队列、外部系统和人员。未知关系可用虚线和说明区分。

Mermaid 的流程方向 TD 适合步骤、LR 适合架构；subgraph 表达边界。时序图声明参与者，alt/opt/loop/par 对应条件、可选、重复和并发。决策节点用菱形，边标签只承载必要含义。

DOT 通过方向、节点间距、层距、曲线和 cluster 改善密集关系；避免全互联造成的交叉。UML 使用 actor、participant、database、queue、component 等语义，类图优先关键字段与方法。SVG 使用 title、分组、矩形、线、箭头和可读文字，避免外部字体/远程图片带来的不可移植性。

## 参考与结果判断

[图形示例](references/diagram-patterns.md) 保留流程、泳道、架构、时序、ER、状态、类、计划、脑图、旅程、DOT、UML 和 SVG 的可编辑表达。

源格式与图像结果分别记录。扩展名和首行语法可判断记法；格式冲突、语法、标签截断、边顺序、字体、输出尺寸与空文件属于不同问题。源文本可阅读不等于图像已生成，显示结果需与实际可见文件一致。
