# 前端 JavaScript 逆向：请求、运行时与复现

来源：skills/js-reverse/SKILL.md

## 主题与范围

对象包括接口签名、加密参数、风控字段，页面请求链路及脚本来源，函数入参与返回值，XHR/Fetch/WebSocket 触发点，以及将页面证据整理成本地 JavaScript 复现材料。PE、ELF、DLL、SO、APK 的二进制结构属于其他知识领域。

## 知识正文

### 页面观察与请求归因（Observe）

目标请求的 URL 或稳定特征、initiator 调用来源、可疑脚本 URL 和初始记录共同限定问题。页面与 frame 上下文、脚本清单和源码搜索用于建立请求与函数的关联；只看到参数名还不能证明参数在该函数中生成。

### 最小侵入采样（Capture）

运行时样例连接静态代码与实际请求：参数样例、函数调用顺序、入参、返回值和命中位置应属于同一事件。XHR/Fetch 触发位置、函数文本位置、暂停时的栈帧和局部变量分别提供请求边界、源码边界及运行时上下文。WebSocket 消息也需要关联其触发来源。轻量观察是否足够，取决于这些证据能否解释目标参数；源码改写和更重插桩会带来额外行为变化。

### 本地最小复现（Rebuild）

页面证据决定入口函数、依赖脚本、调用次序和宿主对象契约。window、document、navigator、crypto、storage 的存在及行为不能仅凭经验假设。时间、随机数、cookie、UA、canvas 等依赖可能解释同一输入产生不同结果。最小复现关注目标链路，而非完整模拟浏览器。

### 环境修正与首处分歧（Patch）

first divergence 指页面行为与本地行为第一次不同的位置；首个异常则可能只是最早暴露的缺口。环境补丁以报错和分歧为依据，单次因果变更的记录应说明缺失对象、观测依据、补丁含义和复测结果。目标是稳定生成目标参数，并解释为何与页面一致，而非只消除异常。

### 语义提纯（DeepDive）

去混淆、控制流恢复和业务逻辑提纯服务于算法理解与长期复用。如果产出只是一次参数样例，语义恢复深度可与该目的相称；若要求长期复用，稳定链路之外还需解释算法与依赖。大规模 AST 清理若先于证据链建立，容易清理错误范围或掩盖环境差异。

### 技术视角的区别

原文中的 js-reverse、jshookmcp 与 anything-analyzer 是历史能力命名：浏览器页面观察、CDP 调试、运行时 Hook、网络证据、SourceMap 重建与 AST 理解可以互补。HTTP 抓包偏请求和响应，运行时视角偏调用栈、函数值与源码归因。名称本身不构成依赖，也不隐含服务连接或工具调用要求。

## 观察与判断

- Observe-first / Evidence-first：以页面事实界定问题，以请求、栈帧和运行时值支撑结论。
- Hook-preferred / Breakpoint-last 是原文的低干扰采样经验；具体观察方式取决于能否取得必要上下文，不是固定 agent 流程。原文同时列出请求断点作为轻量观察，二者应按实际证据需求理解。
- Rebuild-oriented：证据应能解释本地复现，而不只停留在截图或代码片段。
- 无进展的根因可能是请求范围错、运行时证据不足、环境依赖猜错或去混淆范围过大；详见对应知识页。
