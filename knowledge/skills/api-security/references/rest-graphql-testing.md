# REST 与 GraphQL 深度观察

来源：skills/api-security/references/rest-graphql-testing.md

## GraphQL 安全主题

### 内省探测的三个信息粒度

完整内省涵盖 `__schema` 的 `queryType`、`mutationType`、`types`、`fields` 与字段 `type`；精简内省只看类型名；最小探测关注 `__type` 对 Query 类型的响应。原文将其称为三级降级，知识含义是区分完整 schema、有限类型元数据与单个类型可见性。某个粒度被拦截不等于其他元数据不可见。本页不提供查询载荷或固定绕过次序。

### 资源消耗与 DoS 向量

别名过载使单次请求携带许多执行分支；批查询使一次传输承载多个查询；循环关系与深层嵌套提高解析和执行成本；重复指令造成解析、验证或执行负担。四类问题分别观察别名数量、批次数、深度/复杂度、指令和字段计数，并关联响应时间、资源占用与拒绝策略。原文百级别名、十个批次是规模示例，不是安全阈值。

### 授权与请求方法

GET 允许状态改变的 mutation 时，方法语义、CSRF 与会话携带方式可能不一致。混合查询和 mutation 的批次需要逐操作认证、逐资源授权；首个合法查询不能代表整个批次有权限。证据应保留身份、批次中各操作类别、对象归属及各项响应。

## REST API 深度主题

### 方法操控矩阵

| 端点角色 | GET | POST | PUT | PATCH | DELETE | OPTIONS |
|---|---|---|---|---|---|---|
| 用户集合 | 访问基准 | 创建权限 | 批量覆盖范围 | 可写字段边界 | 级联删除范围 | 方法与元数据暴露 |
| 当前用户 | 本人基准 | 业务是否支持 | 自身角色等受保护字段 | 额外字段追加 | 自身删除授权 | 支持方法信息 |

方法之间的业务能力不同，结论来自服务端是否维持相同身份和字段边界，不能只由状态码推断。

### 参数注入与类型边界

NoSQL 运算符对象与字符串之间存在解析语义差异；批量赋值关注 email 等普通字段与 role、isAdmin 等受保护字段是否被同一绑定器直接写入；重复参数关注服务端、代理与框架采用首值、末值还是数组；JSON 数组中的元素也应维持预期类型，不能因数组外形合法而忽略元素语义。原文具体注入载荷已转写为这些结构条件与可观察结果。

### SSRF via API

`webhook_url`、`callback_url`、`avatar_url`、`import_url`、`redirect_uri`、`file_url`、`proxy_url`、`image_url` 都可能触发服务端取回。风险是请求可进入非预期网络、云实例元数据或本地文件协议，绕过浏览器端的访问边界。保留目标类别、重定向与协议处理、响应内容及出站记录等证据；云地址和本地文件载荷不在知识页中复制。

## 从流量与规范得到覆盖面

### 流量驱动规范生成

源材料的 Vespasian 示例表达浏览器流量或 HAR 输入到 OpenAPI 3.0 / GraphQL SDL 输出。规范包含路径、参数、类型、认证和响应；规范归纳的盲区应与流量覆盖范围一起记录，而不将生成文件视为完整资产事实。

### 五种角色视角

| 原概念 | 技术观察目标 |
|---|---|
| malicious_insider | 对象越权、批量赋值、权限扩大 |
| bot_swarm | 限速、资源消耗、自动化滥用 |
| penetration_tester | 输入注入与认证边界 |
| impatient_consumer | 并发竞态和错误处理 |
| confused_user | 意外输入、类型边界和容错 |

这些是历史 Entropy 材料中的角色视角，无需并发代理或固定人格。规范差分、持续集成和结果持久化承载的是回归覆盖目标。

### 全协议覆盖

历史 api.sh 的八阶段分别对应 GraphQL 资产与权限、REST 输入和业务、WebSocket、SOAP/XML 外部实体、限速与 schema 汇总。本页保留全部协议范围，拆成可独立阅读的观察维度，未保留命令或固定管道。

## 证据与报告

报告包含端点/协议、方法与媒体类型、角色/对象矩阵、类型边界、资源计量、实际响应、影响与回归状态。原文来源概念包括 OWASP API Top 10、Praetorian Vespasian、Entropy、FireTail GraphQL，均为背景而非依赖。
