# API 安全知识框架

来源：skills/api-security/SKILL.md

## 适用场景与阅读方式

覆盖 REST、GraphQL、WebSocket、SOAP，以及 JWT / OAuth 2.0 认证、BOLA/IDOR 对象授权、BFLA 功能授权、业务逻辑、限速与资源消耗。OpenAPI/Swagger 文档和实际流量是两种互补的接口证据；文档缺失不等于接口不存在。本页按技术问题组织十个观察维度，维度之间没有固定执行次序。

## API 发现与侦察

API 资产包括浏览器产生的请求、历史 HAR、JavaScript 中的路径、robots.txt、公开接口规范与未文档化的版本。常见规范位置包括 `/swagger.json`、`/openapi.json`、`/api-docs`；GraphQL 服务常见于 `/graphql`。流量到 OpenAPI 3.0 / GraphQL SDL 的归纳，目标是形成方法、路径、参数、响应、身份要求和未覆盖区域清单。历史材料中的 Vespasian、Entropy、Kiterunner、ffuf 分别代表流量归纳、端点提取和路径发现类别，不构成依赖。

GraphQL 内省有完整 schema、仅类型名、最小类型探测三个信息粒度。完整请求失败可能来自策略或资源限制，不能单凭失败认定没有 schema 暴露；不同粒度的响应以及中间层与源站差异才是观察依据。具体字段见 REST / GraphQL 专页。

## 认证：JWT、OAuth 与 GraphQL

JWT 观察头部算法是否被服务端固定，`alg` 是否能选择无签名模式，RSA 公钥是否误被作为 HMAC 对称密钥，HMAC 密钥强度是否足够，`kid` 是否被当作不受限文件或密钥定位器。`exp`、`iat`、`sub`、`role` 等声明需要由签名和业务约束共同保护；能够解码不代表验证成功。

OAuth 2.0 关注 `redirect_uri` 的精确匹配、`state` 与浏览器会话绑定、PKCE 的授权码绑定，以及 code/token 是否进入日志、URL 或 Referer。GraphQL 的 mutation 在 GET 与 POST 中的处理、同一批次中各操作的认证一致性，会影响 CSRF 和混合操作授权结论。

## 授权：BOLA / IDOR / BFLA

对象级授权的证据应同时包含对象归属、请求身份和响应差异。数字 ID、UUID、用户名和邮箱只是不同对象引用形式，不应被当作授权机制。双会话对照可区分本人的合法访问与他人数据暴露；历史 Autorize / AuthMatrix 代表这种对照思想。

功能级授权关注普通用户是否能触达管理功能、GET/PUT/PATCH/DELETE 是否共用权限边界、旧版 API 是否遗漏新版校验、批量对象操作是否逐项鉴权。单个对象通过检查不能证明整个批次都受到保护。权限矩阵可使用 admin、user、readonly 三种角色并记录每个功能的预期与实际结果。

## GraphQL 专项

- 内省与字段建议：schema、错误消息和枚举提示可能暴露类型、参数及关系。
- 别名、批查询、字段重复、指令和循环查询：请求长度、解析成本、执行次数和嵌套深度是不同资源维度；源材料以百级别名、十级批次、数百次重复字段作为规模例子，不能据此推断通用阈值。
- 嵌套关系遍历：顶层对象获准不等于每个关联字段获准。
- GraphiQL / Playground、追踪和调试模式：公开 IDE 与执行元数据可能扩大信息暴露。
- GET mutation：请求方法与状态改变、CSRF 防护之间应有一致约束。

## REST 输入验证

HTTP 方法、Content-Type（JSON、XML、multipart）和字段类型共同决定解析路径。NoSQL 运算符对象与普通字符串的区别、URL 参数触发的服务端取回、XML 外部实体解析、重复参数的优先级和额外字段的对象绑定，是不同的输入边界。批量赋值的核心是客户端可控字段与服务端角色、权限、账户归属等受保护字段未隔离，不能只依靠前端隐藏字段。

## 业务逻辑与差分

API 版本差分记录状态码、响应字段增删和延迟变化，并结合角色与业务步骤解释。优惠券、积分和价格属于业务状态约束；并发请求造成的 TOCTOU 属于检查时间与使用时间不一致，单请求验证不足以覆盖。差分只表明行为变化，风险结论仍依赖业务影响证据。

## WebSocket

观察握手端点、身份继承和 Origin 约束，消息结构、类型边界、超大消息处理与连接资源；跨站 WebSocket 劫持（CSWH）关注跨站来源是否能携带会话建立连接。消息注入与原型污染是原文列出的输入风险类别，证据需落到消息字段和状态变化。

## 限速与资源消耗

`X-Forwarded-For`、`X-Real-IP` 的信任边界会影响限速身份；路径大小写、末尾斜线及规范化差异会影响计数归属。低速长连接、GraphQL 深度与批次、来源地址变化分别反映连接、执行复杂度和身份聚合问题。报告记录窗口、计数键、配额、返回状态和资源指标，不能由一次 429 或一次成功响应推断整体策略。

## 数据暴露

API 返回与 UI 展示不一致可能造成过度暴露；分页上限决定批量读取规模。堆栈、内部路径和 SQL 错误属于错误面信息。GraphQL 嵌套关系、OpenAPI 中的敏感接口也需要与实际权限对照。可观察结果包括字段名、脱敏样例、受影响角色与是否超出业务所需。

## CI/CD 与回归证据

规范变更、权限变更和已确认问题可形成回归样例。构建门禁以严重度和实际影响为依据，记录输入规范版本、角色、请求/响应差异、重现条件与修复后的结果。历史 Escape DAST、StackHawk 代表业务逻辑与开发期检测类别；不规定平台、安装或调用方式。

## 证据与报告结构

报告按资产与版本、认证方式、角色/对象矩阵、输入边界、可观察结果、影响、修复建议和回归结果组织。保留能够解释结论的请求结构、响应差异与截图说明；凭证、真实目标和个人路径用角色标识。
