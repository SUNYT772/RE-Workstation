# 二进制数据库：分析对象与观察字段

来源：skills/ida-reverse/references/ida-mcp-cheatsheet.md

## 适用范围与概念

原文以 IDA Pro MCP 接口速查组织内容。本页按分析对象保留信息语义和完整能力，不列调用名、参数调用示例、启动指令或平台注册资料。IDA 是历史上下文；以下知识不依赖特定实现。

## 核心原理与技术细节

### 启动与会话管理

分析会话包含目标文件、数据库、当前绑定状态和会话标识。列举会话、辨认当前会话、文件间切换、保存进度、释放资源、检查 worker 与整体健康，是不同的状态观察。缓存和反编译系统的准备程度会影响首个请求的耗时。快速可见的数据库与自动分析已经完成的数据库也不是同一状态。

大型或 GUI 样本可能长时间无返回；原日志 `OK:filename:session_id`、`INFO:opening:...` 和超时状态分别表达绑定对象、等待进度与等待上限。临时副本状态应带有与原件的身份对应；原固定 600 秒是历史经验值。

### 全局概览、函数列表与统一查询

概况字段包含 x86/x64/ARM/MIPS 等架构、入口点、函数总数、字符串统计、段和导入分类。加密、网络、文件 I/O、注册表分类帮助形成候选问题；高 xref 函数说明引用密集。原 minimal/standard/full 分别代表简要、标准与完整粒度，不改变这些字段的意义。

函数清单的观察维度包括名称过滤、起始偏移和页大小；全局变量、导入、字符串、命名符号属于不同实体类别。名称包含 crypt/main、导入含 Create、字符串含 http 是原例中的语义线索，名称匹配并不代替行为证明。

### 反编译、反汇编与函数概要

函数可用符号名、自动命名或地址定位。伪代码表达高层逻辑；反汇编包含真实指令与地址，观察范围可按指令数界定。综合函数记录应能关联伪代码、字符串、常量、调用者、被调用者和基本块。多个函数的大小、块数、xref 数可形成概貌对比。

### 交叉引用与调用图

引用目标可能是函数、字符串、数据或导入；例如文件读写导入的引用可映射到真实使用点。引用具有 to/from 方向和类型；被调用者清单与多根调用图呈现不同层次的关系。深度 2、3 等只是局部视图范围。反向数据流说明一个值如何形成，正向数据流说明一个值流向何处，原深度 5 示例仅用于界定追踪边界。

### 搜索

| 搜索对象 | 原例语义 | 观察结果 |
| --- | --- | --- |
| 字符串正则 | URL、Windows 路径、错误/失败/非法信息、密钥/口令/令牌相关词 | 字符串地址、内容、引用及其真实用途 |
| 反汇编文本 | 调用某类函数、寄存器清零等指令形态 | 指令位置及上下文 |
| 原始字节 | 精确序列、多模式、含 `??` 的通配模式 | 命中范围与唯一性 |
| 立即数 | 有意义常量 | 值的位宽、用途和引用路径 |
| 字符串引用 | 某文本被何处使用 | 使用点和关联控制流 |

短字节模式如 `48 8B 05` 可以匹配多处，`48 89 ?? 24 ??` 表示部分位置不固定；连续填充值或对齐字节不一定表示真实功能。

### 内存与数据读取

原始字节记录地址和读取长度；字符串记录地址、编码和边界；整数记录地址和大小；全局值关联符号和类型。结构体读取以地址与类型共同解释内存，结构体名称搜索仅获得候选定义，不能证明布局正确。64 字节原始区域、4 字节整数等原例强调读取粒度，与宿主默认整数大小无关。

### 修改操作：注释、重命名与补丁语义

注释支持单项、批量及追加；反汇编和伪代码中的相同位置需要一致语义。原注释例依次对应解密循环、密钥初始化和结果校验，体现解释按证据逐步完善。函数、全局、局部变量分别具有不同命名作用域，解密函数、验证函数和明文缓冲区等命名要表达已知角色。

汇编补丁可改变单条指令语义，字节补丁改变原始编码。原例涵盖检测指令消除、分支走向改变、返回值改变；本页仅保留变更类别与记录要求，不提供绕过调用或补丁字节配方。可观察结果应能说明具体分支、返回值或状态是否变化，以及哪些原假设仍未验证。

### 类型系统

结构体、枚举、联合体和函数原型共同恢复数据含义。原 PacketHeader 示例具有 `magic:uint32_t`、`type:uint16_t`、`length:uint16_t`、尾部可变长 `data`；这是协议字段知识，字段偏移和实际总长仍取决于布局与对齐。原解密函数示意具有返回整数、缓冲区指针、长度和密钥指针，并带调用约定信息。

类型应用对象包括函数、全局和局部变量；推断结果应与读写宽度、偏移、参数用途相符。按名称查询类型与查看完整定义回答不同问题：前者定位候选，后者核对布局。

### 栈帧分析

栈帧视图包括函数、变量偏移、变量名和类型。原示例中偏移 `-0x20` 与 `char[32]` 表达帧内局部缓冲区；它不是对其他函数通用的覆盖偏移。声明或删除栈变量会改变展示解释，不改变原机器指令。

### 签名生成

地址签名定位局部点，函数签名定位整体，引用签名定位“访问某地址”的代码。签名所含绝对地址、相对位移和编译差异决定跨版本稳定性。命中与唯一命中需分别记录。

### 进制转换

十六进制与十进制转换是同一数值的表示问题，批量结果应保留原输入和输出基数。原例 `0x401000 = 4198400` 展示地址表示一致性；位宽、带符号解释和字节序不由基数转换自动解决。复核时分别核对数值及其表示语义。

### 导出与脚本所承载的信息

JSON 适合结构化保存，C 头文件适合共享类型和声明，原型清单突出函数接口。原数据库脚本示例实际读取的是函数清单、段名、函数范围和大小；这些内容可以作为导出字段理解，不保留执行代码或要求某种接口。

## 观察项与判断依据

### 恶意软件分析

网络、加密、注册表等导入与网络相关字符串是初始线索；引用函数解释通信行为，参数的反向数据流解释密钥来源。记录应能从发现回到字符串、函数、参数及地址，避免把任何网络导入直接认定为恶意行为。

### 注册验证逻辑

serial/license/register/valid 等词可指向验证区域；验证函数、上层调用、输入变换和条件分支构成解释链。原修改跳转示例承载“验证条件变化会影响接受结果”的语义，本页不保留具体绕过操作。

### CTF 逆向

架构、入口和主逻辑确定解释语境；flag/correct/wrong 等文本帮助定位判断点；输入到判断点的数据流及变换算法解释条件。辅助数学计算应对应已识别算法，不凭提示词猜结果。

### 漏洞分析

strcpy/sprintf/gets 等危险接口只能定位候选调用。上下文、实际缓冲区大小、长度计算、调用路径和用户可控来源共同决定是否存在越界风险；栈帧与反向数据流分别解释目标边界与输入来源。

## 故障定位与经验

| 现象 | 对应问题 | 可区分的证据 |
| --- | --- | --- |
| No database bound | 当前上下文未绑定目标 | 会话存在性、绑定对象和目标身份 |
| Failed to open database | 旧库锁、路径或内容问题 | 锁持有者、副本结果、数据库伴随文件 |
| schema 校验失败 | 客户端与结构化结果不一致 | 返回层、schema 字段与真实会话状态 |
| 分析请求超时 | 大文件分析中或 worker 异常 | 进度、worker 健康、会话可见性 |
| 原 ERR:timeout | 服务未达就绪 | 进程状态和就绪状态分别判断 |
| 数值不一致 | 基数、位宽或符号解释错误 | 原始值与转换说明 |
| 函数名找不到 | 名称不精确或命名变化 | 候选函数名、地址与原型 |

## 证据与报告结构

结果记录可以使用“对象身份—范围—字段值—引用关系—判断依据—局限”的统一结构。重点保留关键地址、类型、原始数据、指令/伪代码差异、图边界和可复核输出。会话是否完整、自动分析是否仍在进行、是否使用副本均应可辨识。
