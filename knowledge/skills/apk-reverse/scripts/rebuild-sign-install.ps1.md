## 知识正文

### 输入身份与产物

工程目录是资源/smali 构建来源；输出目录与基础名称决定产物身份，源默认采用工程父目录和工程目录名。unsigned_apk、aligned_apk、signed_apk 分别表示未签名、对齐后与已签名产物。keystore 字段在原材料中表达签名来源位置；clean 页只记录签名身份和来源关系，不承载密钥。

### 状态链与检查边界

重建成功产生 APK；对齐改变归档布局，源实现采用 4 字节对齐参数；签名赋予签名身份；验签检查结果及证书信息；设备结果还需要设备标识和安装/覆盖语义。这些状态不能合并成一个成功标记。源代码分别区分 build、alignment、sign、verify 和设备接受失败，有助于根因定位。

### 签名参数的知识含义

密钥库来源、别名与证书身份用于区分谁签署产物；存储口令和私钥口令是凭据，不进入知识页。源材料的临时调试证书使用 RSA 2048 与 10000 天有效期，这只是历史样例的元信息，不作为建议、安装要求或安全保证；调试身份也不等于原始发行身份。

### 设备与覆盖

DeviceSerial 对应目标设备；Install 表示原材料中是否涉及设备落地结果；Reinstall 仅在该结果被要求时具有覆盖意义。原 Windows 版本即使未选择设备落地也解析设备相关工具，这属于运行实现耦合，不是重建知识的必要条件。

## 观察与判断

可重建不等于验签通过，验签通过不等于与设备已有包签名相容；旧产物与新产物混合可造成误认。本文只描述状态和可观察结果，不执行设备安装或输出清理。
