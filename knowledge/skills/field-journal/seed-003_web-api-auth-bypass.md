## 场景分类
渗透测试

## 目标概述
对某 Web 应用的 REST API 进行黑盒测试，发现未授权访问和 IDOR 漏洞。

## 观察、决策与验证

1. 信息收集：端口/服务观察得到 443 端口运行 Nginx + 后端 API
2. 目录发现：目录发现结果为 `/api/v1/` 路径
3. API 枚举：访问 `/api/v1/docs` → 发现 Swagger 文档暴露
4. 认证分析：注册两个测试账号 A 和 B
5. 测试 IDOR：用账号 A 的 token 访问账号 B 的资源 → 成功（水平越权）
6. 测试未授权：去掉 Authorization header → 部分接口仍返回数据（未授权访问）
7. 验证影响：确认可读取任意用户的个人信息（姓名、邮箱、手机号）
8. 证据收集：保存请求/响应截图，脱敏后整理报告

## 失败路径与诊断

| 问题 | 原因 | 解决方案 | 耗时 |
|------|------|---------|------|
| FFUF 被 WAF 拦截 | 请求频率太高触发限流 | 原记录以降低请求频率和普通浏览器 UA 区分流量策略影响 | 10min |
| Swagger 文档 404 | 路径不是标准的 /swagger | 尝试 `/api/v1/docs`、`/api-docs`、`/openapi.json` | 5min |
| IDOR 测试不确定是否成功 | 返回的数据没有明显的用户标识 | 对比两个账号的响应，找到 user_id 字段差异 | 15min |
| 报告被 SRC 拒绝 | 只提交了截图没有完整复现步骤 | 补充可复核的请求结构、身份与对象关系、完整请求/响应及结果差异 | 20min |

## 能力与格式知识


- 原素材比较 FFUF 与 Gobuster 的发现效率，但未给统一测试条件；可迁移观察是请求频率、WAF 策略和限速会改变覆盖与返回。
- Swagger/OpenAPI 文档可揭示已声明路径、方法和字段；文档与运行接口版本不一致时，不能把文档枚举等同于实际覆盖。
- IDOR 判断以两个自有测试账号、已知对象归属和响应字段作为真值，而不只比较状态码。
- 原素材中的仅截图报告被拒，反映请求结构、身份与对象条件、完整响应和结果差异对复核的重要性。

## 技术机制与证据


原请求对照包含同一对象在账号 A、账号 B 和无 Authorization 三种状态下的响应。输入为资源标识与测试主体，结果为状态、字段和归属；200 且确有受保护数据才支持未授权结论。目标域、令牌与字典路径角色化，发现命令不保留。


## 可迁移经验


- API 专项知识需要同时覆盖认证、对象授权、功能授权、资源消耗和数据暴露，单一路径列表不能代表完整边界。
- IDOR 的可读对象范围、字段敏感度和角色差异决定影响；一个越权样本不能直接推广为任意用户或全部接口。

## 算法与结构

**API 未授权测试三步法**：

认证对照的三个状态是本人正常响应、无 token 响应、另一测试主体响应。它们分别解释基准、缺少身份时的边界和对象授权，不要求按固定次序执行。


**IDOR 快速验证**：

两个自有测试账号的对象 ID 与所属数据构成已知真值；A 身份读取 B 对象且返回 B 数据，是水平越权证据。响应无明显身份时需要字段差异和对象归属联合判断。
