# 经验材料的脱敏与语义保留

来源：skills/field-journal/anonymization.md

## 来源性质与目标

本页是匿名化规范知识，不是项目成果。源材料借鉴 PentAGI 的角色占位思想，目标是在不暴露真实对象的前提下保留机制与证据关系。本 clean 副本按用户要求进一步将工具调用和载荷转为原理，未沿用源文“通用 payload 原样保留”的做法。

## 占位符总表

### 网络与主机

目标、受害/下一跳、远程、服务器/中转、回调、目标域、内部域和自定义端口分别用 `{target_ip}`、`{victim_ip}`、`{remote_host}`、`{server_ip}`、`{callback_domain}`、`{target_domain}`、`{victim_domain}`、`{port}`。标准端口如 80、443、22、445、3389 保留协议意义，不代表真实目标部署。

### 凭证与密钥

用户名、密码、身份哈希、会话、API、Cookie 和 Bearer 分别使用 `{username}`、`{password}`、`{hash}`、`{token}`、`{api_key}`、`{cookie}`、`{bearer_token}`。不同身份及不同时期的秘密有不同角色，不能全部混成一个 token 而丢失跨主体关系。

### URL 与端点

`{url}`、`{api_endpoint}`、`{callback_url}`、`{upload_endpoint}`、`{login_endpoint}` 表达资源角色。保留版本、路径层级、方法和参数类型可解释 API 机制，域、业务 ID 与秘密替换。

### 路径

安装、配置、Web 根、上传和日志路径分别为 `{install_dir}`、`{config_path}`、`{webroot}`、`{upload_dir}`、`{log_path}`。个人主目录、用户名和开发者 PDB 路径角色化；标准系统路径或协议格式可保留为知识位置。

### 业务标识

真实姓名、邮箱、手机号、工号、订单、UUID 对应 `{user_name}`、`{user_email}`、`{phone}`、`{employee_id}`、`{order_id}`、`{uuid}`。管理员、普通用户、租户 A/B 等角色要保持稳定，以支持越权证据。

## 技术语义的保留边界

CVE、工具历史名称/版本、标准端口、公开 OS 名称、库/函数、协议/字段应保留。源文还允许通用 payload，本副本改为说明解析机制、输入结构与观察结果，避免复制载荷。真实样本身份摘要与凭据哈希不同：样本 SHA-256 可用于指代材料，密码/认证哈希不能因此公开。

## 上下文保留原则

全部替换为 X 或过于通用的 target/url 会丢失关系；“目标地址”“管理路径”“管理员会话”分别标识地址、业务和权限语义，更能解释因果。同一对象在多处一致占位，不同对象避免误合并。角色化之后仍应看得出数据来自谁、经过哪层、影响哪个身份/资源。

## Payload 脱敏的知识化

### Web

原样例包含资源层级、用户标识、查询参数、Host 与会话 Cookie。清理后保留方法、参数解析边界、对象归属和会话角色；注入内容改为“查询语义被改变”的机制，不保留请求载荷。

### Shell

原反向连接涉及远端、端口、标准输入/输出和进程解释器。知识只记录网络连接与进程 I/O 被关联的结果；地址/端口角色化，同时移除命令与重定向字符串。

### 动态插桩

应用包、Crypto 类型、decrypt 输入和密文属于不同角色。保留方法签名、输入类型、返回/调用关系和观察结果；实际包、密文/密钥替换，拦截与替换代码移除。

## 二进制样本脱敏

### 哈希与样本

源建议记录 SHA-256 而不附二进制，公开样本库名属于历史情报背景。本次只整理文字，不上传或共享样本。摘要是否本身具有客户保密属性与材料来源有关，不能把公开样本惯例套到所有内部材料。

### 字符串与符号

硬编码 Bearer/JWT、业务 URL、开发者和组织标识需要角色化；OpenSSL、memcpy 等公共符号保留。字符串的长度、编码、字段作用和来源可以解释机制，无需保留秘密字节。

## 截图脱敏

用户名、邮箱、电话、订单、姓名、企业 Logo/水印与 URL host 可能泄漏身份。路径结构可按角色表达，内部网络可模糊到前两段（如 10.0.x.x），但网络角色和是否跨网段仍需可理解。文字中的脱敏不能证明截图已清理，截图证据是独立检查面。

## CTF 素材的来源性质

公开题面、格式与主机标识在源语境中通常公开，但私有靶场、未结束比赛的 flag、尚未公开的他人解法不能混同。这里的 seed 文件均是 [种子] 方法素材，不是已验证真实实战；不保留实际 flag 或接收目标。

## 自动检测的原理与局限

源 PowerShell / Bash 示例寻找非私网 IPv4、邮箱、中国大陆手机号和三段 JWT。知识目标是候选标识发现，不是证明绝无泄漏。IPv4 的排除集合为 10/8、127/8、172.16–31、192.168；原正则没有严格校验每段 0–255，也未覆盖 IPv6、编码秘密或所有域名。源 Bash 示例使用与其正则方言不完全兼容的负向前瞻，不能把输出为空当无泄漏。工具脚本和运行命令不复制。

## 阅读他人脱敏文档

占位符表达原角色，不需要回填为自己的真实环境。角色保持稳定能保留比较与证据链，回填可能引入与原案例无关的泄漏和事实错配。

## 经验页的证据检查维度

网络/域、秘密与会话、截图个人信息、二进制附件、内部地址、载荷目标参数、Cookie 与 OAuth 标识属于不同面。报告同时说明技术语义是否完整和敏感值是否移除，不以统一检查表限制 Agent 或强制发布流程。
