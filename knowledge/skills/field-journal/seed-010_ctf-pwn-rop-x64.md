## 场景分类
CTF / 二进制利用

## 目标概述
一个 64 位 ELF，存在 `read()` 越界写入栈缓冲区。本机有 NX（不可执行栈）但无 PIE，无 stack canary。原目标是解释 ROP、libc 与系统执行影响，不复制命令字符串。

## 观察、决策与验证

1. 基础侦察
   
原 ELF 为 x86_64、动态链接、未剥离符号；NX enabled、No PIE、No Canary、Partial RELRO 分别描述不同保护边界。字符串只是线索，保护状态与具体读写缺陷需要联合解释。

2. 用 IDA / Ghidra 看 main → 发现 read 允许 0x100 字节，而栈缓冲区只有 0x40 字节
3. 计算溢出偏移
   
循环模式与崩溃位置用于估计覆盖返回位置，原样例得到偏移 72。这个值对应当前栈布局，不能推广到其他二进制；本页不保留生成/输入调用。

4. 由于没 PIE，PLT 和 GOT 都是固定地址
5. 第一类证据（缺少 libc 身份）：动态 puts 地址与库基址的关系
   
原第一阶段把动态链接表项中的运行时地址与静态符号联系，并回到可继续交互的程序状态。泄漏值、符号偏移、库版本与会话状态是核心证据，不复制 ROP 序列。

6. 接收 puts 输出，定位 libc 版本（用 libc-database 查询）
7. 第二类证据：目标函数、参数与库基址的关系
   
原第二阶段说明已知库基址与目标函数/参数地址的关系。控制流受 NX、ABI、栈对齐和运行库版本约束，原命令字符串和 payload 拼接不保留。

8. 原最终验证为控制流影响与赛事结果，flag 值不保留

## 失败路径与诊断

| 问题 | 原因 | 解决方案 | 耗时 |
|------|------|---------|------|
| ROP 调用 system 后程序崩溃，没 shell | 栈未对齐到 16 字节（Ubuntu 18.04+ 对 movaps 严格） | 原故障定位到 16 字节 ABI 对齐，额外返回边界改变栈位置；不保留 gadget 序列 | 30min |
| 本地能打通，远程打不通 | libc 版本不一致 | 运行时符号与候选库版本对照；单一地址可能不能唯一确定版本 | 40min |
| pwntools recv 卡住 | 程序输出用了 setbuf(NULL) 但远程未关闭 stderr 缓冲 | 输入提示、输出分隔符与连接状态的同步证据 | 15min |
| 一打远程就 SIGPIPE | 第二阶段 payload 还在使用上一轮的 io 对象 | 用 `process` / `remote` 之后 io 依赖同一有效连接，主进程死了就完了 | 20min |
| ROPgadget 输出太多 | 工具默认列所有 gadget | 按指令类别缩小候选集合，输出数量不是缺陷本身 | 5min |

## 能力与格式知识


- pwntools 在原素材中表达交互、二进制打包与符号管理；pwndbg 表达循环模式、映射与堆状态观察，不保留量化优越性判断。
- ROPgadget 与 ropper 表达指令片段及控制流约束检索，格式友好与否不证明片段在目标上下文可用。
- libc-database 的符号地址匹配会产生版本候选，单个地址未必唯一，仍需基址和其他符号证据。
- one_gadget 的历史概念关联局部控制流条件与运行库版本，不保留执行目标或序列。

## 技术机制与证据

地址、连接与 ABI 的关联：


完整脚本承载的技术点为同一连接中的两阶段状态、字节序、短地址补全、符号偏移与库基址、输入提示同步和 16 字节栈对齐。原示例地址 0x401243 / 0x40101a 属于局部样本，不作可复用目标；本页保留算式“库基址=运行时符号地址−同版本符号偏移”和验证依据，不复制攻击脚本。


## 可迁移经验


- x64 栈偏移、NX/PIE/canary、运行库版本、地址解析和栈对齐共同决定解释是否成立；这些条件比某个现成模板更能说明失败原因。
- 原素材中的固定偏移仅对应其二进制，泄漏地址、运行库候选与实际调用边界应保持可追溯。

## 算法与结构

**ROP 利用决策树**：


保护矩阵中 NX 影响栈数据执行，PIE/ASLR 影响地址确定性，Canary 影响返回控制数据完整性，RELRO 影响动态链接表可写性。原文提及 ret2libc、格式化字符串、off-by-one、fork 地址继承、__libc_start_main 与 SROP，仅作为历史相关类别保留，不增加解决分支或利用步骤。


**libc 泄漏 → 利用 标准两阶段 payload**：


两阶段模型的知识是地址证据与后续控制流依赖同一版本、同一运行状态及有效连接；原具体 gadget/字符串/函数顺序不复制。
