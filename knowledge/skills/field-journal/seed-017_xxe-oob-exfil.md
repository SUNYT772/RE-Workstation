## 场景分类
渗透测试 / Web 漏洞利用

## 目标概述
某 Web 接口接受 XML 请求体（SOAP / 上传 docx 解析 / 自定义 API），不回显内容（即"盲 XXE"）。利用外部 DTD + 参数实体技巧把目标文件外带回攻击者服务器。

## 观察、决策与验证

1. 探测点
   - 任何 Content-Type 含 `xml` / `soap` / 文件上传 docx/xlsx/pptx（含 XML）/ SVG
   - 注入测试 payload 后看响应：报错 / 时延 / OOB 回连
2. 首先试有回显的简单 XXE
   
原有回显例说明 XML 外部实体解析可能把本地资源纳入文档结果。doctype、实体解析开关、资源协议与输出通道是前提，不保留 XML 载荷或目标文件地址。

3. 无回显但 OOB 通 → 用外部 DTD
   - 在自己 VPS 上放 evil.dtd
   - 触发服务器加载并外带
4. OOB 也不通 → 看是否能用 error-based / blind boolean
5. 拿到 /etc/passwd 后扩展面：
   - 内网端口扫描（XXE → SSRF）
   - 读应用配置文件（数据库密码 / 私钥）
   - 触发 SSRF 打云元数据 → 见 seed-006

## 失败路径与诊断

| 问题 | 原因 | 解决方案 | 耗时 |
|------|------|---------|------|
| 直接 SYSTEM "file://" 报错 | 解析器禁用了 ENTITY 引用 | 一般实体与参数实体的解析策略不同，源替代载荷不保留 | 30min |
| 文件含 `<` `>` `&` 导致 DTD 解析爆炸 | XML 规范禁止参数实体里有特殊字符 | 字符编码与流包装影响 XML 特殊字符及输出表示，不保留包装载荷 | 40min |
| OOB 服务器 80 端口收到回连但 payload 没拼接好 | DTD 嵌套层数搞错 | 外层 DTD 与内层实体的声明/展开上下文需一致 | 1h |
| 文件读取了但只读到一半 | XML 限制实体长度（XML_MAX_TOKEN_BYTES） | 长度限制影响观察完整性，源分段外传方案不保留 | 1h |
| 内网 SSRF 全是 connection refused | 应用所在网段没开内部服务 | 网络命名、路由、目标服务状态与连接拒绝需分开解释，不保留替代探测地址 | 30min |
| Java 应用打不通 | Java 默认 XML 解析器禁了 SYSTEM | 协议支持、SOAP 解析器与 Java 库版本是独立前提，原替代探测方案不保留 | 数小时 |

## 能力与格式知识


- XXEinjector 在原素材中表示 XML 实体处理结果的归纳；Burp Collaborator/interactsh 表示带外事件关联，不构成运行依赖。
- DNS-only 与 HTTP 带外观察具有不同出站可达性，域名解析发生不等于文件内容已外带。
- docx 是 ZIP/XML 组合，word/document.xml 和实际 XML 解析配置决定上传链风险；SVG 同样需要解释实际解析器和外部实体策略。
- payloads-all-the-things 仅是原参考资料名称，不沿用“最全”排名，也不复制其载荷。

## 技术机制与证据

OOB 标准两层 DTD（内带 base64 文件外带）：

**evil.dtd（放在攻击者 VPS）**：


外部 DTD、参数实体与数据编码存在层次关系；源示例利用 PHP 流包装改变资源表示。知识页保留解析阶段、字符约束与外部资源角色，不复制 DTD 外传模板。


**目标请求体**：


原请求体将主文档与外部 DTD 的解析上下文关联。实体声明、远程引用、参数实体展开和最终资源请求是不同阶段，不能由收到一次访问推断文件内容已外带。


**攻击者起 HTTP 服务收数据**：


带外事件中的编码值、解码后内容与原请求需要唯一关联。原 HTTP 服务启动、外传接收和账户文件内容不复制；结果统一为〈本地文件内容〉角色。


XXE → SSRF 内网扫描：


XML 解析器的网络取回可能跨越到服务端内部网络，形成 SSRF 类影响。协议支持、出站策略和实际响应决定可达范围，不保留内部管理 URL。


错误回显（error-based）—— 让 XML 解析器在错误信息里返回内容：


错误回显例把资源内容引入解析失败上下文，关键观察是错误消息中是否出现不应公开的数据。解析错误本身不证明内容泄漏，不复制故意失败的 XML 构造。


**docx 上传 XXE**（很多文档处理类应用受影响）：


docx 是 ZIP 容器与 XML 部件组合，word/document.xml 是源例的解析入口。上传、解包、解析器设置和错误/网络结果需要关联，不保留修改并重新上传的代码。


## 可迁移经验


- OOB、error、blind、docx upload 与 SVG 是不同入口/反馈条件，知识记录需说明解析器、实体策略、回显、出站能力和结果证据。
- 一般实体与参数实体、DNS 查询与 HTTP 请求、外带片段与完整文件具有不同语义，不能互相替代验证。

## 算法与结构

**XXE 类型决策树**：


回显、错误、无回显与 DNS/HTTP 连通表达不同观察通道。原决策树改为证据层：实体是否展开、资源是否访问、内容是否进入输出/事件，各层不能自动等同。


**XXE 协议清单（按解析器测试）**：


源协议表列 file、http/https、ftp、gopher、expect、jar、netdoc。支持范围取决于解析器、运行库、扩展与配置；本地文件、网络、归档与执行能力是不同语义，不应由语言名称推断全部支持。


**DNS exfil（最弱通道）**：


DNS 名称可承载与处理内容相关的标识，源例将主机名与外部域关联。此页只保留关联与数据泄漏判断，不复制 DNS 外传载荷或编码方案。
