# 逆向工程先例的技术知识

来源：skills/field-journal/precedent-reverse.md

## 来源性质与阅读范围

源文件把命令和模板称为本机已执行先例，但未提供逐项项目证据。本页把它们保留为能力、格式、输入输出与失败条件目录，不能据此声称本次执行或全部真实验证。授权覆盖、固定读序、安装与调用均不保留。

## APK / Android 逆向

### 包、资源与代码表示

APK 包含 DEX、资源、manifest、native 库与签名。源 jadx / apktool 示例覆盖 Java 可读表示、DEX 与资源分离、smali、资源跳过、重建和签名后的可安装状态。原参数注释中“跳过资源”和“跳过 dex”存在组合语义风险，本页按输入/输出层说明，不能把命令名当成功结果。

安装状态、设备进程与 logcat 是运行环境证据，USB 可达、目标包/进程与版本需要对应；安装与运行命令不保留。证书签名、文件字节和安装验签共同决定重建产物是否可运行，调试 keystore 口令已移除。

### Java、native 与业务定位

sign/signature、HMAC/MD5/SHA、encrypt/decrypt、AES/RSA/Base64/token 等词是代码位置线索，不是算法证明。native 声明、System.loadLibrary / System.load、JNI_OnLoad、静态/动态注册表把 Java 方法连接到 native 地址。类枚举与方法观察输出签名、参数和结果，不能因类名相似自动确定业务用途。

### 场景与失效前提

OkHttp CertificatePinner / check$okhttp3 属证书 Pinning，运行时框架端口/组件名属于自检输入，加固样本的内存 DEX 与磁盘内容可能不同。IL2CPP 的 libil2cpp 与 global-metadata、Flutter 的 libapp 与 snapshot、smali 的签名校验调用是源场景。它们分别需要格式/版本/地址与运行结果证据，不保留反检测、绕过签名或注入调用。

## IDA / Ghidra 的技术对象

### 静态与地址证据

格式识别、架构、基址、自动分析与数据库产物不同；地址定位、字符串、交叉引用、伪代码、函数/变量名、类型声明和数据导出彼此印证。源快捷键和 IDAPython 被改为这些对象关系。重命名/类型是分析假设，导出 C 数组与实际数据字节属于不同表达。

### 平台场景

自解压 ELF 的运行内存与磁盘代码不同；stripped Go 的符号结构与导入映射改善阅读，但不等于源码恢复；Rust crate 字符串提示依赖；.NET 的 IL 适合托管语义；Mach-O 的 ObjC 头与 native 地址互相补充；UEFI 的映像区域、基址和 DXE 驱动决定地址解释。原 UEFI 的省略基址只是示意，不能填为真实值。

## 动态插桩：输入、时机与输出

Java 层的方法签名、参数、原返回值与最终结果构成最基本观察；native 层需要模块、导出或基址+偏移、ABI 和参数有效性。JNI NewStringUTF 的语义是以 UTF 输入创建 Java 字符串，不能仅凭该接口宣称数据方向一定是 Java 到 native，原注释的方向歧义保留为判断风险。

证书上下文/TrustManager 是独立信任边界，RegisterNatives 把名称、签名与函数指针映射起来。源脚本中的 Interceptor / NativeFunction 调用改为这些结构，没有复制拦截器或替换实现。

多进程应用需要把目标业务与进程对应；线程清单不能代替进程身份。延迟加载意味着类存在时刻与开始观察时刻不同；无导出名可通过同版本模块和偏移关联；只读内存范围与读取结果仍要验证地址/长度/来源。原 spawn/attach、自检端口、maps/ptrace 等表示时序与观察面，不规定动态工具。

## CLI 表达的二进制知识

| 对象 | 原命令承载的技术内容 |
|---|---|
| 文件类型与字符串 | 真实格式、编码、公开关键字与可能业务引用 |
| 二进制属性 | 架构/位数、NX、PIE、Canary，各属性含义独立 |
| 导入/导出 | 外部能力声明与可引用符号 |
| 节区/重定位/库 | 文件布局、装载修正与依赖 |
| 函数/伪代码/交叉引用 | 入口、边界、控制流和引用关系 |
| 字节与补丁 | 地址、文件偏移、原内容及改动内容的一致性 |
| Go | 版本、pclntab/符号、包名与类型信息 |
| Rust | 模块路径、符号修饰与 Cargo 依赖 |

原 radare2/rabin2 的每类查询和写入目标均由上表覆盖，不保留命令序列。

## 二进制修改与产物一致性

指令改写、字节改写、文件偏移写入、反向编码、APK 重新打包签名、iOS 动态库依赖与自签名，是原修改类别。静态地址不总等于文件偏移，修改后的签名/加载/启动需要独立证据。源 iOS 自签名并不自动绕过所有 code signing；环境前提应明确，不保留注入/安装命令或 NOP 写入。

## 反调试 / 反分析的观察表

| 原检测面 | 输入与反例 |
|---|---|
| TracerPid / ptrace | 当前追踪状态、调用时机，进程选择影响结果 |
| 单步时间 | 时钟与调度/延迟，慢不一定证明调试 |
| 端口与组件名 | 默认端口、进程和框架字符串，只是环境特征 |
| maps | 映射内容与模块身份，不直接等于恶意行为 |
| 签名 | 实际字节、可信签名与业务校验三层 |
| root / su / Magisk | 权限环境与具体路径/调用 |
| 模拟器 Build 属性 | MODEL / MANUFACTURER 与真实硬件的差异 |
| D-Bus | 协议/组件行为与观察通道 |
| TLS callback / int3 | 常规入口前的初始化及异常时序 |
| 虚拟机 | CPUID、注册表、MAC 与环境基线 |

原表的改变返回值、改端口/名字、删除调用、跳过异常和模拟硬件方案转为这些输入与观察，未增加方法。
