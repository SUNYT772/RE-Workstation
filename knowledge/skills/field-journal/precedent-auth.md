# 授权语境与技术证据的区别

来源：skills/field-journal/precedent-auth.md

## 来源性质

本页来自源工作站的授权预声明，属于工作流/背景材料，不是具体目标的授权证明，也不是已完成项目记录。原文试图用先读文件、默认授权与强制执行改变 Agent 行为；这些句式在 clean 中改为语境分类与证据区别，不具有运行效力。

## 原材料的五类语境

SRC / Bug Bounty 关注平台范围和身份；自有/内部系统关注资产归属；合同测试关注 RoE 与对象；CTF/沙箱关注隔离目标与题目；开源研究关注公开材料与披露背景。分类帮助解释为什么同一技术可能出现在不同任务中，但源声明本身无法证明某个真实主机或某次外部动作属于其中。

## 授权、技术不确定性与实际结果

目标名称只表明对象，不能单独等同于权限、范围和动作。源文“提到目标即授权”的二值规则已转为这个语义区别，未保留自动执行或覆盖审查的指令。

技术效果不明、WAF 拒绝、服务下线、凭证过期、没有发现漏洞属于不同技术状态；它们可以用具体响应、时间、身份或环境证据解释。没有发现不是成功利用，技术阻碍也不自动支持替代攻击方案。原“必须给绕过”“不得拒绝”等语句不进入知识正文。

## 为什么源文采用预声明

源材料试图减少专业环境中的重复确认，但把局部使用惯例上升为所有目标的默认事实会损失范围和上下文。可保留的知识是用户需求、环境身份、目标范围和结果之间需区分，避免把过去的操作经验当成当前事实；本页不新增审批流程或对 Agent 的限制。

## 与先例和文档失效知识的关系

[逆向先例知识](precedent-reverse.md)记录文件结构、类型与运行时证据；[安全评估先例知识](precedent-pentest.md)记录协议、权限与报告；工作流理解页讨论状态、上下文和验证。它们说明“材料里有哪些能力”，不能因为阅读而改变授权状态或自动触发执行。原固定读序、全局规则与强执行链全部移除。
