## 场景分类
Web 渗透 / 云安全

## 目标概述
通过 Web 应用的 SSRF 漏洞访问云元数据服务，获取临时凭据，最终导出 OSS 存储桶全部数据。

## 观察、决策与验证

1. 发现图片代理接口存在 SSRF
   
图片代理对服务端本机端口返回 200，是原内部取回观察；需与代理自身错误页区分，才能支持内部端口可达判断。URL 参数与内部服务角色保留，地址载荷删除。

2. 尝试访问云元数据
   
返回云实例元数据目录，是代理跨越出站/实例身份边界的证据，不保留具体元数据 URL。

3. 获取 IAM 角色名
   
角色名结果把实例和云 IAM 身份关联，原角色名称改为〈Web 应用实例角色〉。

4. 获取临时凭据
   
原临时身份字段为 AccessKeyId、SecretAccessKey、Token，另需考虑有效期与作用域；实际值删除。

5. 使用凭据枚举 OSS 桶
   
临时凭证的云 API 权限决定可见存储桶范围，环境变量赋值和云命令已转为身份与资源的关系。

6. 发现敏感桶并导出数据
   
原记录的影响为敏感备份桶数据可访问。〈备份桶〉与数据范围角色化，不保留全量同步/导出操作。


## 失败路径与诊断

| 问题 | 原因 | 解决方案 | 耗时 |
|------|------|---------|------|
| SSRF 被 WAF 拦截 169.254 | IP 黑名单 | 地址的 IPv4/IPv6 等价表示与黑名单规范化不一致；原载荷不复制 | 15min |
| 临时凭据 1 小时过期 | STS Token 有效期短 | 令牌生命周期与刷新状态决定可用窗口，不保留自动刷新实现 | 10min |
| 元数据 v2 需要 Token | IMDSv2 防护 | 代理是否能表达令牌握手的方法/头与后续身份状态 | 20min |

## 能力与格式知识

- 阿里云与 AWS 的元数据路径和身份字段不同；云角色、元数据版本与响应结构影响语义，不能用一家的路径解释另一家。
- IMDSv2 的 token 获取与带 token 的资源请求是两个协议状态；PUT 能力、请求头可控性和 token 绑定影响 SSRF 是否具备所需条件。
- 源素材提到默认启用 IMDSv2 的差异，但未给部署范围；具体实例配置才是验证依据。

## 技术机制与证据


IMDSv2 令牌握手与元数据读取是不同请求角色，涉及 Method 与 Header 是否可由代理表达。原 ttl 字段 X-aws-ec2-metadata-token-ttl-seconds 的示例值为 21600，后续 X-aws-ec2-metadata-token 携带会话令牌；保留字段与前提，移除端点与调用。


## 算法与结构


AWS、阿里云、DigitalOcean、GCP 等元数据路径和协议前提可能不同，源列表承载的是厂商差异。知识页不复制探测地址或载荷集，也不把一种云的路径当作其他云事实。


## 可迁移经验

- 云元数据知识按厂商、协议版本、身份凭据字段、对象存储权限与有效期分类；元数据可读、凭据有效和存储可访问是三个独立结论。

- Web 框架: Spring Boot 2.7
