# 2026-05-15 lumine v0.9.1：Go TLS 分片代理逆向

来源：skills/field-journal/2026-05-15_lumine-go-reverse.md

## 案例问题与环境

目标为 Windows amd64 的 PE32+、Go 1.24.5、约 11.6 MB，原版本 v0.9.1。问题是将二进制行为恢复为可读 Go 源码，重点为逻辑重建而非声称逐行恢复原始源码。TLS 分片代理的技术背景关联 Python TlsFragment，原仓库当时返回 404，使来源比对受限。

## 观察、决策与结果

符号恢复得到 1,944 个 Go 函数，其中 269 个来自项目；包名/函数名线索提示 12 个包。`config.json` 的反序列化行为与函数引用一起帮助恢复类型和字段。源码重建覆盖 core engine 与 dial（出站绑定）、errors（错误类型）、format（字符串工具）等子包。

原文前置说明称“七个包源码重建”，产物段则称“七个 Go 源文件，core engine 加三个子包”，与识别出十二个包是不同计数口径；本页保留数字及其语境，不补造其余包。

## 技术发现

TLS 记录分段、噪声、ACK 时序、OOB 与 Fake TTL 是源分析识别的核心机制。域名 Trie 与 IP Trie 共同支持 Policy 匹配；DNS/TTL 缓存具有 LRU 特征，源名 go-freelru 保留为历史依赖概念，不规定安装或使用。这里不扩写网络规避操作。

## 失败路径与诊断

| 问题 | 原因与决策 | 原验证或限制 |
|---|---|---|
| Windows 的 Python3 路径异常 | WindowsApps stub 与完整解释器不同 | 环境身份应以实际解释器为据，不保留安装命令或个人路径 |
| 子进程路径中的 `~` | 不会在所有调用环境中自动展开 | 路径展开后的具体位置与存在性决定结果 |
| tab / space 混合 | 生成脚本的缩进影响输出源码格式 | 原 v3 使用一致空格后消除该格式问题 |
| 缺少 vendor 符号 | Go 1.24.5 下函数名可恢复，但参数/局部变量信息不足 | 结构恢复与原变量信息恢复不是同一能力 |
| 标准库字符串噪声 | 静态链接引入大量无关常量 | 包级过滤有助于把项目证据与 runtime 分开 |

## 能力、产物与可迁移经验

源 GoReSym v1.7.1、Capstone 与 pefile 分别承载 Go 符号、指令和 PE 结构解释能力。原“latest”是环境记录，不作为版本要求。原产物为完整逆向报告与 v3 重建源码目录；它们在源文中存在，未链接包外，也未在本次运行生成或验证。

可迁移经验为：函数边界/包名、配置类型和业务行为相互校验；大量符号恢复不代表参数与局部名可恢复；源码文件数量、包数量和识别范围需要分别报告。
