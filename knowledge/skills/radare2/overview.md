# 二进制侦察：定位、粒度与证据

来源：skills/radare2/SKILL.md

## 适用范围与概念

原材料覆盖 PE、ELF、Mach-O、DEX、WASM，以及 EXE、DLL、SO、APK 中的二进制内容。问题包括反汇编、函数分析、字符串、导入导出、交叉引用、补丁、差分和十六进制解释。CLI、交互模式、批量模式和 r2pipe 是历史呈现与自动化方式，不构成知识使用条件。

GUI 伪代码、网页 JavaScript 逆向与动态调试各有不同的观察对象。本模块聚焦不依赖 GUI 的结构侦察与局部代码解释。

## 核心原理与技术细节

### 环境确认所承载的目标

原版本检查和路径探测的实际目标是确认结果来源、实现版本和可用能力；缺失依赖、环境变量刷新与文件本身无法解析是不同原因。原可执行文件清单包括 radare2、rabin2、rasm2、radiff2、rahash2、rax2、r2pm，其中包管理属于运行资产，不随知识页保留安装方式。

### 侦察与深入分析的粒度

文件格式、架构、位数、平台、入口、字符串和导入表能够低成本建立解释范围。全量自动分析可能增加耗时与噪声；常规自动分析、更加深入的全量分析和入口周边定向分析是不同粒度，信息完整性与消耗并不相同。大样本中，局部分析所得函数清单不能误写成全文件清单。

原“最小足够命令”原则转写为信息目标：只需要格式时，结果应集中在格式；只需要字符串或导入导出时，结果应对应这些对象。输出规模与问题范围一致，比罗列所有功能更有解释力。

### 原侦察脚本与参考页

原侦察资源承载六类输出：基本信息、节区、导入、导出、字符串及可选自动分析摘要。脚本本体属于运行资产，未复制。参考页保留这些字段与局部定位的观察语义，不再要求复用或调用某个脚本。

## 观察项与判断依据

### 快速侦察

文件身份包含格式、位数、架构和平台；入口点提供控制流起点。URL、路径、报错、注册表和命令行参数可作为语义线索。网络、文件、加密、进程注入和注册表导入说明潜在能力，但仅有导入不能证明真实执行。节区布局和导出也有助于辨认加载及接口边界。

### 函数与交互式分析

局部函数视图包含函数清单、字符串、节区、符号、入口、当前函数反汇编和控制流图。当前定位地址影响显示结果；函数不存在可能是分析粒度或函数边界识别问题。常规自动分析与更重的分析深度应作为结果上下文说明，终端是否适合可视化不影响底层控制流事实。

### main 与关键逻辑定位

main、入口点、带符号函数、http/error 等字符串可以形成候选位置。字符串地址与引用点的对应，把“发现文本”变成“文本在哪个函数、什么条件下被使用”的结论。引用点所属函数的反汇编和分支条件才是解释错误消息的直接证据。

### 十六进制与内存查看

原例分别观察当前地址起 64 字节、20 条指令和当前字符串，强调“字节数”与“指令数”不能混淆。十六进制视图、带注释的字节视图、字符串视图和反汇编提供不同解释层；编码、起始地址和范围需要明确。

### 二进制 patch

读取与持久写入是不同的状态。原写汇编、写原始字节、保存退出承载的知识是：指令语义对应编码，文件修改需要持久化才会影响下次加载。原例涉及空操作和条件/无条件分支变化；本页保留修改类别、目标地址、旧/新语义、原件身份和修改后反汇编核对，不提供补丁配方或写入调用。

### 非交互自动化

原自动分析、安静输出和命令串分别控制分析状态、展示噪声及批量内容。其技术目标是让一次结果清楚呈现函数、字符串、导入等不同数据集，避免无边界长串掩盖错误。可读的结构化结果有助于区分分析失败、空结果和未分析区域。

### 常用子能力的历史分类

| 历史名称 | 技术能力 | 应保留的结果语义 |
| --- | --- | --- |
| rabin2 | 静态信息提取 | 基本信息、节区、符号、导入、导出、字符串及更广范围字符串 |
| rasm2 | 汇编与反汇编 | 架构、位数、字节编码与指令语义的对应 |
| radiff2 | 两个二进制对比 | 字节级与代码级差异及地址范围 |
| rahash2 | 哈希 | MD5/SHA-256 等算法名、文件身份和摘要 |
| rax2 | 进制与编码转换 | 原表示、目标表示、数值或文本含义 |

原数值例 `0x401000` 与 `4198400` 表示同一地址，文本编码转换与数值基数转换是不同问题。哈希相等的比较需使用相同算法及相同输入范围。

## 故障定位与经验

### Windows 下偶发 .sdb 缺失告警

原 PE 侦察曾出现 `Cannot find ...\share\format\dll\*.sdb`。若主体字段仍正常返回，该告警可能仅影响附加格式数据库，不足以判定整次侦察失败。结论应说明哪些字段有值、哪些信息缺失、缺失是否影响当前问题。

### Windows 路径、环境与权限

带空格路径容易在参数解析层被截断；可执行程序查找失败可能是 PATH 刷新问题。目标不可读与解析错误需要区分。原动态调试和权限提示转写为证据语境：静态读取、动态运行与读取受限目录具有不同的状态与副作用，报告应准确说明结果如何取得，不从静态内容推断已运行。

### 三类典型请求

“这个 EXE 做什么”需要格式/字符串/导入支撑的初步解释，再由入口及关键函数确认；“报错在哪触发”需要字符串地址、引用函数与触发条件；“条件跳转变化”需要修改位置、前后指令语义及重新解码的一致性。原固定操作序列已转写为每类结论所需的证据关系。

### 常见误判

只看自动分析摘要不等于理解程序；缺基础侦察时难以解释架构与入口；只列命令不等于分析；网页脚本与 native 指令并不共享相同的格式和执行模型。写入状态混淆还可能使内存显示与磁盘文件不一致。

## 证据与报告结构

结果适合包含侦察概况、关键字符串、导入、函数及地址、引用关系、局部控制流解释、已证实行为与尚待验证假设。修改类记录增加原/新内容、文件身份与反汇编核对。输出中解释为什么这些证据支持结论，相关知识可按问题需要继续展开，不限定 agent 执行阶段。
