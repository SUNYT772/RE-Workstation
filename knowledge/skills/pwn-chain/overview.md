# 内存损坏：保护条件与环境一致性

来源：skills/pwn-chain/SKILL.md

## 适用范围与概念

原材料以已知溢出、UAF、double free、整数错误、竞态和内核 ioctl 问题为前提，讨论从故障到控制流影响的工程差距。这里保留栈/堆/内核知识与稳定性依据，区别于 fuzz/审计发现漏洞、通用逆向理解程序和网络攻击链整合。本文是原知识转写，未运行二进制、连接远程端或生成利用程序。

## 核心原理与技术细节

### 漏洞类型与保护机制

目标架构、位数、动态依赖和加载环境定义代码语义。NX 约束数据页执行，canary 检测部分栈破坏，PIE 与 ASLR 影响代码/库位置，RELRO 影响重定位表写保护，Fortify 涉及部分 `_chk` 接口和长度检查。漏洞还需区分栈、格式化字符串、堆 UAF/DF/OF、整数、竞争与内核对象损坏。

### 原策略分类的知识语义

原 NX/ASLR 与 shellcode、NX 与 ret2libc/one_gadget、未知 libc 与符号指纹、堆与 glibc 版本、内核与凭据/helper 等分类，表达的是“控制能力必须满足保护与布局条件”。这些不是可机械套用的决策树；知道覆盖点并不自动获得所需地址、状态或对象控制。

### 地址、符号与 gadget

库中符号观测地址与同版本符号偏移的差，可解释运行时基址：`base = observed_symbol_address - matching_symbol_offset`。版本不一致会让这个差失去意义。gadget 描述的是指令片段对寄存器、栈和内存的状态变化；可找到片段并不代表前置条件和后续控制流都成立。

### 本地、调试与远程状态

原模板的三种连接模式承载三个环境：本地进程、调试进程和远端服务。架构、libc/loader、ASLR、输入输出分隔、进程派生、堆布局和 CPU 保护可能不同，因而本地一次成功不足以解释另一环境。工具调用与 payload 拼接不保留，状态差异与观察指标保留。

### 稳定性判断

libc 错配可能在已进入库函数后崩溃；64 位栈对齐问题可能表现为 movaps 附近异常；远程收包分片、提示符时序和缓冲可能表现为“输入无反应”；堆布局与相邻 padding 对象影响合并和重用。原固定等待时间与模糊 sleep 的经验转写为“用协议边界解释何时完成收发”，不是调用特定 I/O API。

原材料给出 20 次以上和≥95% 的稳定性目标，这是原研究口径，不作为本页限制 agent 的固定测试次数。记录成功/失败分布、失败位置与状态条件，比单次成功更能说明稳定性。

## 观察项与判断依据

### 64 位 ELF 的源场景

原例具有 NX、PIE、canary，提供 libc，读入范围 0x200 而局部缓冲区只有 0x40。各量代表输入上限与存储边界，不等于返回地址覆盖偏移。canary、代码基址、库基址、寄存器状态和栈对齐是不同条件；拿到一种地址或值不自动满足其他条件。原链式 payload 不复制，分别保留这些条件及其与失败现象的关系。

### Linux 驱动 ioctl 的源场景

原对象包括 vmlinux、bzImage、initramfs 和自定义模块，copy_from_user 的受控长度导致内核堆越界，保护含 SMEP、SMAP、KASLR、KPTI。源码称 kmalloc-64，并泛列 tty_struct/msg_msg/pipe_buffer，后者实际尺寸在参考页各有不同；不能把这些对象都当作同一 64 字节缓存适配。

原修改 init 直接获得高权限是实验环境便利配置，不是漏洞提权证据。基址、对象重用、控制流、凭据与安全返回是彼此独立的观察面；直接将控制流移到用户地址还会受到 SMEP/SMAP 的约束。具体提权链和 helper payload 未保留为执行步骤。

### 历史工具链的能力转写

pwntools 表示进程/协议与数据表示背景；GEF/pwndbg 表示寄存器、映射、栈与堆观察；ROPgadget/Ropper 表示片段索引；one_gadget 表示带状态约束的库片段；libc-database 表示符号指纹；QEMU 表示内核环境；binwalk/cpio 表示镜像结构；patchelf 表示 loader/依赖对应。它们不构成依赖列表，安装与失败后重试规则不复制。

## 故障定位与经验

### 版本与地址

不能用操作系统发行版标签替代实际 libc 身份。原 tcache 在 2.27、safe-linking 在 2.32、hooks 在 2.34 的分组为源材料历史简表；具体分界和发行版回补需要目标证据，相关风险见堆知识页。内核地址差值只在相同构建和对应区域内有意义；原“一次 leak 足够”的概括不涵盖函数粒度随机化或独立模块。

### 对齐、缓冲与时序

movaps 类对齐异常需要结合实际栈状态；返回片段对栈的消耗能够改变对齐，但不能仅凭“加一条返回”认定全部状态正确。收发的提示符、分隔、长度、超时与连接生命周期共同解释协议状态。堆喷射数量不是唯一变量，合并、缓存类别与进程模型也影响重用。

### CPU 与内核配置

SMEP、SMAP、PKU、KASLR、KPTI 和实际启动配置决定哪些地址域可执行/可访问。实验中禁用随机化或提升启动用户权限会改变前提，不能把它们当作漏洞结果。原固定 agent 阶段和完成清单已转成证据完整性关系。

## 证据与报告结构

可记录二进制和依赖身份、漏洞类别、保护机制、故障位置与覆盖范围、地址/布局依据、对象生命周期、协议状态、重复观察分布、环境差异及结论限制。源模板中未实现函数或占位偏移不作为已验证方案。
