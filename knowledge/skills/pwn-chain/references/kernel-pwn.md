# 内核对象、保护与返回状态

来源：skills/pwn-chain/references/kernel-pwn.md

## 适用范围与概念

保留 Linux 内核内存损坏、镜像与配置、slab 对象、保护机制、地址观察、凭据和用户态返回知识。原启动、调试、提权、编译与运行模板被转写为对象关系和观察条件，未生成可执行 payload。

## 核心原理与技术细节

### 环境对象

bzImage 是压缩启动内核，vmlinux 是未压缩分析对象，initramfs.cpio.gz/rootfs.img 是启动文件系统，内核模块承载驱动接口，原 run.sh 表达启动参数，`.config` 表达构建配置。它们的构建身份必须对应，文件名相同不证明来自同一内核。

### initramfs 与 init

原 gzip/cpio/newc 例说明压缩层与归档格式分开，init 决定初始用户、挂载和启动逻辑。源将 setuidgid 1000 改为 0 的例仅改变实验启动权限，并不证明漏洞成功；重新打包后的内容也属于不同环境资产。本页不复制拆包、权限修改或重新打包命令。

### 从 bzImage 识别 vmlinux

原 extract-vmlinux 是压缩镜像恢复背景。未压缩代码、符号表和完整调试信息是不同层次：有 ELF 不等于有所有符号，有符号也需与运行镜像相符。知识页不获取脚本或执行恢复操作。

### QEMU 参数与保护状态

原启动例包含内存 256M、串口 console、无图形、禁重启、oops/panic 行为及调试端口；这些决定日志、故障后状态与观察范围。它还显式禁用了 KASLR，所以不能把固定地址实验直接外推到随机化环境。

| 原保护标记 | 技术目标 | 对状态解释的影响 |
| --- | --- | --- |
| SMEP | 限制内核执行用户页 | 用户地址不能直接视作内核可执行目标 |
| SMAP | 限制内核访问用户数据 | 数据/栈所在地址域与访问状态有关 |
| PKU | Protection Keys | 需区分键权限与页/模式权限 |
| nokaslr/kaslr | 禁用/启用地址随机化 | 代码地址是否随启动变化 |
| KPTI/pti | 用户/内核页表隔离 | 返回路径与页表状态相关 |

这些是原参数承载的知识，不是启动配方或工具依赖。

### 调试的观察面

运行内核、对应 vmlinux、故障函数和暂停时刻共同构成调试上下文。寄存器、结构体和内存能说明 ioctl 或其他入口如何处理输入。原推荐的 GEF fork 与 pretty-print 属历史实现名称；本页保留结构体可读性目标，不保留远程调试连接或断点命令。

### 漏洞类型分流

| 类别 | 原来源示例 | 解释所需状态 |
| --- | --- | --- |
| 内核栈溢出 | copy_from_user 长度 | 缓冲边界、canary、返回状态、地址 |
| 内核堆溢出 | kmalloc/slab 相邻写 | 缓存类别、邻居对象、覆盖范围 |
| UAF | 引用计数/重复释放 | 已释放对象、重用身份、残留使用 |
| 整数溢出 | 大复制与小分配 | 位宽、分配和访问长度 |
| TOCTOU | 指针二次读取 | 两次观察间的对象/内存变化 |
| race | 并发入口 | 共享对象、调度与窗口 |
| 任意读写候选 | 已有数据访问能力 | 真实范围、权限与目标身份 |

userfaultfd/FUSE 是原时间窗口背景，cred/helper 是原全局对象背景；不提供拖延、触发或写入实现。

### slab 喷射的对象知识

可控对象大小、缓存类别、释放/重用和相邻对象决定内存损坏落点。原记录的尺寸表为示意，受内核版本与配置影响：

| 原 size 标签 | 对象 | 原关注字段/属性 |
| --- | --- | --- |
| kmalloc-64/96 | seq_operations | 函数指针 |
| kmalloc-1024 | tty_struct | ops 指针 |
| kmalloc-4096 | pipe_buffer | 管道数据与操作关联 |
| 8–4096+ 可变 | msg_msg | 消息数据与大小 |
| kmalloc-128 | user_key_payload | key payload |

源总览曾把不同对象泛列在 kmalloc-64 场景，不应据此认定它们能在同一缓存相互替代。表中数值不作为通用布局常量。

### msg_msg 示例的字段

原示例包含消息类型 mtype 与 mtext 数据，头大小用 0x30、总对象用 0x80，数据部分因此为 0x50；这是具体布局演示。创建对象、内核消息数据和返回数据之间的对应可说明是否发生非预期改变。知识页保留消息结构、大小和读回证据，不复制队列操作或喷射代码。

### 凭据路径：prepare_kernel_cred 与 commit_creds

原链式例的知识对象是凭据创建/选择、凭据提交、返回指针及其作为参数的传递关系；前提不是“有某符号”而是实际控制流和状态可达。源例涉及返回值 rax 与参数 rdi 的对应，以及从内核回用户的完整状态。

用户态 cs、ss、rflags、rsp 和返回 rip 是不同字段；缺失或不匹配会导致返回故障。原 `swapgs_restore_regs_and_return_to_usermode +22` 是特定 trampoline 布局示意，不能移植成固定偏移。本页不保留提权 ROP 序列、寄存器设置代码或 shell 函数。

### modprobe_path 与用户态 helper

原文以 modprobe_path 指定模块辅助程序为背景，讨论内核发现未知可执行格式时的 helper 行为。其安全意义是可写全局路径可能影响高权限 helper 目标；vmlinux 符号与受限 kallsyms 是原地址来源。这里保留触发类别、全局变量角色、权限与配置依赖，不复制路径改写、未知 magic、临时脚本、setuid 或执行 payload。

### core_pattern

该配置影响 coredump 处理路径，原材料讨论其管道 helper 语义及崩溃条件。关键对象是处理配置、进程异常和实际 helper 行为，不能把它与 modprobe 条件混同。本页不提供劫持字符串或处理程序。

### CR4、SMEP 与 SMAP

原例指出 CR4 的 bit 20/21 关联 SMEP/SMAP，说明 CPU 控制寄存器状态会改变地址域权限。原固定 CR4 值和跳转链不保留；“比直接凭据路径更短/更稳”的比较属于原经验，不作为普遍利用结论。

### KASLR 地址观察来源

| 原来源 | 原限制或背景 | 能解释的信息 |
| --- | --- | --- |
| /proc/kallsyms | kptr_restrict 与访问条件 | 符号观测值 |
| /sys/module/.../sections/.text | 模块与访问条件 | 模块代码区域 |
| dmesg/oops | dmesg_restrict 与日志内容 | 异常现场地址 |
| 未初始化栈/堆 | 残留内容可读 | 候选指针，需验证身份 |
| msg_msg 与越界读 | 对象读回范围 | 对象或邻居数据 |
| Meltdown/Spectre | 原记录强调非通用，KPTI 相关 | 旁路历史背景 |
| SIDT/SGDT | 老内核历史现象 | 地址披露背景 |

原纯换算关系为：运行时内核区域基址等于已确认符号地址减同构建符号偏移。某个内核地址不必然解释独立模块或函数粒度随机化。本页不复制地址采集脚本。

### 完整 exploit 模板的状态结构

原骨架声明用户返回状态、基址、多个待填符号偏移、内存区域、驱动文件描述符和未实现 trigger/leak 函数。它不是可直接使用的通用程序。知识上保留“观测基址—同构建符号—受控状态—内核入口—权限/返回结果”的关系，未补写占位偏移、触发函数或用户态执行链。

### 学习参考：CVE-2022-0185

原记录将 fs/fs_context.c 的 legacy_parse_param 长度与有符号/无符号混淆关联到 kmalloc 堆越界，并以 user namespace、msg_msg、UAF 重占用和跨缓存为学习主题。CONFIG_USER_NS、非特权命名空间可用性、消息与管道对象差异、地址可见性是原案例的前提。

Crusaders of Rust、Openwall 2022-01-18 讨论、willsroot 与 PortSwigger 收录是原资料名称；本次未访问或运行公开 PoC。原“换成 pipe_buffer”“增加地址观察”属于练习任务，转写为对象尺寸/缓存与地址来源的比较目标，不补充新利用技术。

## 观察项与判断依据

根因、内存对象、大小类别、保护、实际 CPU/配置、地址来源、凭据状态和用户返回状态需要逐层关联。启动时就以 root 运行、禁用 KASLR 和调试时序变化属于环境差异，不能用来证明目标漏洞已完成提权。

## 故障定位与经验

CONFIG_RANDOM_KSTACK_OFFSET/RANDOMIZE_KSTACK_OFFSET_DEFAULT 的随机偏移影响固定栈位置，源称范围 0–1023，具体粒度取决于实现。CONFIG_SLAB_FREELIST_RANDOM/HARDENED 影响对象顺序和链字段假设；增加对象数量不保证重用位置。

CONFIG_STATIC_USERMODEHELPER/static_usermodehelper_path 使原 modprobe 路径假设失效。KPTI 的页表与返回 trampoline 关系不能简化成任意 swapgs/iretq；FG-KASLR 使“单地址加统一偏移”不再覆盖所有函数；CET/IBT 及 ENDBR 约束间接目标和片段可用性。

串口 printk 会改变时序，竞态现场可能因此消失。原寄存器标记与观察例表达“减少观测扰动”的目标，未保留调试命令或固定 magic 值。源中的通用化说法需要放回目标配置，不能仅按内核主版本推断。

## 证据与报告结构

记录镜像/模块/符号一致性、构建配置、init 权限、保护状态、漏洞入口和字段、slab/对象布局、生命周期、地址/基址依据、异常与返回状态、凭据观察、调试扰动及前提限制。完整模板的占位部分和未实现函数保持为不完整性的说明，不转成新 payload。
