# 栈、ABI 与控制流条件

来源：skills/pwn-chain/references/stack-pwn.md

## 适用范围与概念

本页保留栈损坏、覆盖定位、调用约定、ret2libc、ret2csu、one_gadget、符号基址及远程状态故障知识。原进程/网络/调试调用和可执行 payload 模板转为结构说明，不生成新的攻击代码。

## 核心原理与技术细节

### 触发条件与保护字段

| 原检查字段 | 技术含义 | 判断需要的证据 |
| --- | --- | --- |
| NX disabled | 某数据区域可能可执行 | 真实页权限、地址与控制流可达性 |
| Canary found | 部分栈破坏可能被检测 | canary 所在位置、检查路径及值的来源 |
| PIE enabled | 主程序位置可随机化 | 运行时映射与代码地址对应 |
| No PIE | 主程序代码通常使用固定布局 | 目标实际加载情况 |
| Full RELRO | GOT 等重定位区域受写保护 | 真实映射与目标对象 |
| Partial RELRO | 部分重定位区域未同等保护 | 可写范围不能仅凭标签扩大 |
| FORTIFY | 部分 libc 调用具有 `_chk` 变体 | 具体调用、缓冲区长度与实现 |

原表将 read_chk 与 strcpy_chk 作绝对对比，知识上保留其检查差异主题，但不能脱离具体参数和实现就判定前者一定可溢出、后者一定不可能。源中“NX 与 ASLR 关闭”说明直接执行内存内容对页权限与地址可预测性的依赖，不是充分条件。

### 栈溢出长度精确定位

循环唯一模式使被覆盖字节与输入偏移对应，core dump 中 fault_addr 或 RSP 指向内容提供观察。原 200 字节模式是实验长度，32 位截取与 64 位取样表达不同匹配宽度。模式位宽、端序、截断、实际异常地址与保存返回地址的位置不能混淆；命中模式只说明偏移证据，不代表保护已满足。

### 32/64 位 calling convention

| 架构/ABI | 参数角色 | 返回值 | 原注意点 |
| --- | --- | --- | --- |
| x86 cdecl | 栈参数 | eax | 返回地址后为参数，调用者清栈 |
| x86-64 SysV | rdi/rsi/rdx/rcx/r8/r9，再到栈 | rax | 调用边界具有 16 字节对齐约束 |
| ARM32 | r0–r3，再到栈 | r0 | lr 保存返回地址 |
| ARM64 | x0–x7，再到栈 | x0 | 栈对齐和调用约定需对应真实代码 |

表是原简表，不能把 x86-64 SysV 直接等同于所有 64 位平台；call/ret 对栈指针的影响也属于对齐解释的一部分。

### ret2libc 模板所承载的结构

原模板包括文件与 libc 身份、本地/调试/远程三个环境、覆盖偏移、PLT/GOT/符号引用、一次地址观察、库基址换算、返回业务入口和后续库函数状态。它把“观察已加载函数地址”与“按同版偏移解释库布局”分成两层，原示意 OFFSET=0x48 和 gadget 地址都不是通用常量。

观测数据可能短于指针宽度，端序和缺失高字节的解释影响数值。输入输出锚点与回行边界解释收到的数据是哪一段；简单去除空白还可能改变二进制值的解释。原库函数、参数字符串与 payload 拼接不复制为运行链，保留参数、返回地址、布局和环境的关系。

### 栈对齐坑

源现象是本地可用而远程在库函数进入后 SIGSEGV，原因候选为 system/do_system 内的 movaps 对齐要求。amd64 的一次 ret 消耗 8 字节，因此会改变栈指针模 16 的状态。原“末位 0x8 或 0x0”的说法依赖观察点，报告应说明是调用前、入口还是实际内存操作时，而不是套用单个末位结论。

### ret2csu

原 `__libc_csu_init` 例展示两类状态变换：一组恢复 rbx、rbp、r12–r15 并调整栈；另一组将 r15→rdx、r14→rsi、r13d→edi，并通过 `[r12+rbx*8]` 间接调用。低 32 位 edi 与完整 rdi 的差异会影响参数解释，rbx 递增及与 rbp 的比较决定循环能否结束。

原 rbp 与 rbx+1 相等、后续额外栈消耗及 bss 中函数指针例，强调寄存器、间接目标、循环条件和栈布局需同时一致。源“glibc<2.34 静态程序都有”是过度概括，知识页将它作为历史模式，是否存在以实际目标指令为据，不保留可执行链布局。

### one_gadget

该名称表示库中一段在特定寄存器/内存状态下进入预期库路径的片段，而不是无条件跳转目标。原三组例分别涉及 r15 与 r12、r15 与 rdx、rsi 与 rdx，约束为寄存器本身为空或其指向内容为空。位于某个符号偏移只说明位置，不说明状态约束满足。

原 2.34+ 某些版本约束难满足的经验，说明库版本与状态可控性重要；原 e3afe/e3b01/e3b04 偏移属于特定例，不是可复用目标地址。

### libc-database 反查

多符号地址的低位特征可筛选库版本；原 puts/read 的低位例和 libc6_2.31-0ubuntu9.9_amd64 只是格式示例。筛选结果与真实文件、架构、符号偏移的对应需要核对，不能把一个低位匹配视作唯一版本证明。

纯地址换算关系为 `library_base = observed_symbol_address - same_build_symbol_offset`。原在线查询、下载和 API 集成不保留，符号表与观测值的对应关系保留。

### ROPgadget/Ropper 速查的知识语义

原检索涵盖寄存器恢复/返回、syscall、特定指令形态、字符串与 JSON 记录。片段记录应能说明地址、指令、寄存器变化、栈消耗和相关约束；不同架构的覆盖能力是历史实现差异。检索命中并不等于完整状态可控，本页不复制检索或调用代码。

## 观察项与判断依据

### 远程稳定性

| 现象 | 原原因候选 | 需要区分的状态 |
| --- | --- | --- |
| 本地成功、远程库中异常 | libc 版本错 | 文件身份、符号、加载基址 |
| 库函数进入即异常 | 栈对齐 | 实际 rsp、异常指令及访问地址 |
| 只收到半段 | 网络分片/延迟 | 记录长度、分隔、超时与连接关闭 |
| 输入后无反应 | 提示符或缓冲 | 对端是否到达接收状态 |
| 概率性结果 | ASLR 或部分地址猜测 | 地址稳定性和成功率分布 |
| 小包聚合 | TCP Nagle/缓冲 | 数据边界与到达时机 |

原两秒 timeout 和完成接收、1/16 成功率例都是历史经验值，不作为固定控制策略。明确协议锚点比任意等待更能解释状态。

### 调试观察对象

寄存器、内存映射、栈链、GOT、字符串、当前代码和 gadget 索引共同解释故障。原 attach/启动调试、跟随 fork 子进程与条件输出模板转写为“正在观察哪个进程、哪个地址、哪一时刻”的证据语境，不保留调试器命令。

## 故障定位与经验

fork 子进程可能继承 canary，原按字节猜测的例说明进程模型影响状态一致性，不复制猜测循环。格式化字符串可能暴露栈值，其中 canary 与库地址是不同对象；本页不提供扫描格式串。DynELF 是原通过读原语解释动态符号的历史概念，速度与可读范围受具体原语影响，原“万能”不作保证。

静态链接场景不能假定具有动态 libc GOT，原 SROP/syscall 仅作为既有控制流概念索引保留，不扩展链式方法。NX、canary、PIE、RELRO 和实际覆盖范围必须分开解释。

## 证据与报告结构

记录架构/ABI、页保护、覆盖偏移与取样宽度、异常指令与栈状态、符号/库身份、观测地址与基址计算、参数约束、进程模型、协议边界和失败分布。原模板中的地址、主机、端口和执行链不作为知识资产复制。
