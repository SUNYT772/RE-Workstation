# 攻击链场景模型

来源：skills/attack-chain/references/attack-playbooks.md

## 阅读方式

原六种 Playbook 的能力和信任边界均保留，线性的工具流水线改为路径模型。每个节点描述已知事实，每条边描述前提与可能影响；文档不规定调用、安装或代理阶段。

## Playbook 1：外网 Web 应用与域环境

外部资产包括子域、端口、技术组件和已知漏洞假设。Webshell / RCE 表示外部输入跨越到应用承载身份；主机地址、ARP、账户等信息说明网络与身份上下文。隧道与内部服务可达性、凭据材料、PTH/WMI/PsExec 等远程管理能力、目录图、Kerberoasting/DCSync/约束委派又是不同边界。

路径成立需要证明每个身份及资源关系，不能由一个 Web 漏洞直接推出域控权限。原工具链从资产归纳到目录图与证书权限，承载的是这些证据类型。失败点可能是网络隔离、凭据范围或目录权限不满足；对应记录局部前提而非扩张推断。

## Playbook 2：钓鱼与内部影响

公开员工信息、邮件身份/主题、宏/LNK/ISO/HTML 载体、回连行为、本地身份、凭据、远程访问和持久对象构成原场景。入口是否被接受、代码是否真正运行、回连是否发生、权限是否改变是不同观察结论。材料、邮件系统、终端和网络分别可能产生拦截或失效；回连本身不证明后续影响。原发送与制作载荷命令未保留。

## Playbook 3：近源接入

WiFi 信号、门禁、USB 端口是物理可达性；伪造热点/WPA、键盘型设备和网络植入对应无线认证、主机外设信任及网口接入。内部接入点建立以后，网络路由和身份权限仍需要独立证据，不能与已控制内部主机等同。近源与外部 Web 场景共享内部资产和目录关系，但不存在固定的后续动作。

## Playbook 4：云环境

子域与 CNAME 可提示云服务归属；S3/OSS/Blob 公开访问、SSRF 与云元数据、临时 AK/SK/Token、IAM/EC2/Lambda/RDS、PassRole/AssumeRole、跨账户/区域和数据边界分别是原场景节点。临时凭据的权限、区域和时效决定影响。公开存储、获得元数据、获得可用身份和具备管理权限不能混为一谈，报告需要逐层证据。

## Playbook 5：Bug Bounty / SRC

资产和前端 JS、技术指纹、参数清单构成问题入口。对象/角色越权、SSRF、SQL、XSS、文件上传和支付/验证码/密码重置逻辑是原逐类覆盖内容。单项发现的提交材料包括条件、脱敏证据、业务影响与重现说明；本页保留问题类别与报告结构，不复制 PoC、工具调用或持续任务配置。

## Playbook 6：AD CS 证书信任

AD CS 服务、ESC1–ESC8 模板配置、证书申请者与所代表身份、NTLM/TGT、目录复制权限是原文节点。关键是模板用途、可控名称和权限如何影响认证主体。证书可签发不自动等于目标身份可认证；认证成功也不自动授予目录复制能力。路径结论需分别记录证书属性、身份映射与目录权限。

## 通用决策矩阵的知识表达

| 已知状态 | 可解释的知识问题 |
|---|---|
| 仅有域名 | 关联资产、端口与服务证据是否完整 |
| 已知 Web 漏洞 | 影响停留于数据还是跨越到应用/系统身份 |
| 低权限 shell | 令牌、可写来源、配置与高权限对象的关系 |
| 一台内部主机 | 内部网络可达性、认证范围及隔离 |
| 域用户凭据 | 目录 ACL、委派、模板和身份图 |
| 域管哈希 | 认证材料与目录复制/票据信任的影响 |
| 云 AK/SK | 角色策略、时效、账户/区域与资源边界 |
| 钓鱼回连 | 运行身份、终端检测与后续权限前提 |
| 近源接入 | 接入层控制与内部资产/身份的区别 |

## 证据结构

每个场景均可表达为资产节点、身份节点、权限边、入口条件、观察结果、失败前提、影响与剩余未知。历史工具名只用于解释原材料能力，不构成依赖或执行指令。
