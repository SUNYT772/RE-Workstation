# 逆向经验笔记：格式、状态与证据判读

## 阅读定位

本页按原资料的二级、三级主题完整保留经验条目。每条给出其技术对象、可观察关系和适用边界，具体展开见同模块相应知识页；本页自身保留实质内容，不以导航替代正文。原命令、工具安装、固定工作次序、补丁输入、密钥和平台注册信息不复制。历史案例的断言与已验证事实区分表达，不访问原记录中的服务。

## 二进制类型（Binary Types）

### Python .pyc

`.pyc` 的头部与 Python 版本相关：原记录列出 2.x 常见 8 字节、3.0–3.6 常见 12 字节、3.7 以后常见 16 字节的布局。头后是版本相关的 code object 序列化，不是可直接当源码的文本。关键对象包括字节码、常量、名称与局部变量，反汇编解释也要与版本一致；头长本身不足以唯一判定全部变体。

### WASM

二进制与 WAT 文本是同一模块的不同表示；函数、导入、导出、线性内存和比较常量构成校验逻辑。原“转成 C、编译”承载的是获得更易阅读语义的目标，原“改 WAT”承载的是观察比较/常量变化的目标，不规定转换器或编译器依赖。观察应注明原模块与重表示后的对应，避免误把宿主运行时差异当模块逻辑。

### Android APK

APK 同时承载资源、清单、DEX 和 native `.so`。`res/values/strings.xml` 的字符串可提供线索，但 Java/Kotlin 层与 native 层的真实校验可能不同。资源解码、字节码反编译的目标是恢复入口、事件、参数和资源引用关系，不能只因发现可读 flag 样字符串就认定它被实际消费。

### Flutter APK（Dart AOT）

`lib/arm64-v8a/libapp.so` 与 `libflutter.so` 共存支持 Dart AOT 的判断。这里需要恢复应用函数、对象布局、快照和引擎版本关系，不能按普通 Java 校验器解释。原 Blutter 描述的能力是重建 Dart 符号和运行观察辅助材料；名称是历史背景，不作为依赖要求，也不复制其调用脚本。

### .NET

托管程序集保留 CLR 元数据、类型和方法关系，IL 与反编译代码可互相说明。原 dnSpy、ILSpy 分别代表调试/反编译视角；技术目标是定位入口、资源、字符串及真实比较，区分反编译器重建语法和原始 IL 的实际分支。

### UPX 与打包格式（Packed）

原资料遇到 UPX 解包失败时，关注节名、头字段和版本标记是否被修改。这是故障定位依据：识别到 UPX 字样不保证布局仍兼容，失败也不自动证明算法不同。结果应说明压缩数据、加载 stub、元数据异常和原始入口之间的关系，不保留解包命令或安装步骤。

### Tauri 桌面资产

Tauri 可把 Brotli 压缩的前端资源内嵌于可执行文件。`index.html` 的交叉引用可指向资源索引表，索引里的范围与压缩 blob 对应，解压后恢复 HTML/JS 等内容。原源码位置 `tauri-codegen/src/embedded_assets.rs` 是结构背景；不能把所有附近字节都当单一 Brotli 流，需保持索引长度与边界。

## 反调试观察（Anti-Debugging Bypass）

原经验覆盖 Windows 的 `IsDebuggerPresent`、PEB.BeingDebugged、`NtQueryInformationProcess`，Linux 的 `ptrace(PTRACE_TRACEME)` 与 TracerPid，及入口前 TLS 回调。时钟差值可能来自 `rdtsc`、`clock_gettime`、`GetTickCount`；硬件断点线索涉及线程上下文中的 DR0–DR3。INT3 扫描、`.text` CRC、自哈希、SIGTRAP/SIGALRM/SIGSEGV 处理器则可能同时承载反分析与真实控制流。

Frida/DBI 检测的原观察项包括进程映射、特定监听端口、inline hook 字节。端口或单个 API 的出现不是充分证据，应说明检查结果如何流向退出、延迟、诱饵或真实计算。原修改寄存器、改分支与替换函数返回值已转为“比较条件改变前后的路径和返回约定”；不包含补丁、绕过调用代码或固定执行要求。

## 专门模式（Specialized Patterns）

### S-box 与字节流特征

Xorshift32 常见移位组为 13、17、5；原记录的 Xorshift64 相关组为 12、25、27，并关注 `0x2545f4914f6cdd1d`、`0x9e3779b97f4a7c15` 等常量。常量只是候选特征，必须结合移位方向、乘法、状态宽度和输出取位，才能区分状态更新、最终乘法与其他混合函数。

### 自定义 VM

VM 的基本对象是寄存器、内存、IP、opcode 分派与输入字节码。`executeIns` 一类函数可能揭示指令含义，但还需保持操作数格式、分支和比较条件。字节码可能来自参数指定的文件而非主文件。分块密钥链可呈现 3 字节候选域与前后状态传递；块间顺序依赖和块内独立性不同，原并发编译细节不构成知识要求。

### Python 字节码校验

XOR 检查器可能把奇偶位置分别保存在两张表。需要把表的索引、迭代顺序、输入字节与 XOR 参数关系对应，而不是直接连接两表。字节码版本、常量加载和切片语义决定可恢复的原表达式，源码缺失时仍可保留这些依赖。

### 信号树探索

UNIX 信号可能充当二叉树或状态机的边，处理器安装与后续信号选择共同决定可达状态。处理器注册表、信号编号、当前结点与终止条件组成图。原截获 `sigaction` 和 DFS 代码已转为“恢复信号到转移的映射”，不保留信号发送程序。

### 环境检查与条件变化

样例中 JZ/JNZ、睡眠常量和环境条件会决定真路径或假路径。原修改动作的技术含义是隔离一个判断对输出的贡献；需要记录原条件、改变后的条件、返回约定与其他副作用。分支翻转不证明得到的结果是原条件下的自然行为。

### 期望值表

比较指令附近的只读数组、与输入长度相近的元素数、循环索引和终值使用关系，是寻找 expected table 的线索。表可以是字节、字、向量或编码数据；范围、端序、stride 和比较宽度都必须由消费者确认，不能只按可打印性认定含义。

### x86-64 的位宽陷阱

32 位寄存器写入通常清零对应 64 位寄存器高半部，而 `movsx`、`movsxd`、`cdqe` 执行有符号扩展。低字节运算、32 位截断和 64 位比较混合时，无限整数模型会偏离机器语义。结果应标注每一步宽度、扩展方式及比较的带符号性。

### 逐位置候选与统一映射

若每个输入字节只影响一个对应输出，可构成最多 256 项的局部映射。若不同位置变换相同，还需要位置无关证据；映射有碰撞时应保留候选集合。原逐字节求解经验建立在独立性与前缀可判定性上，不能泛化到有扩散、反馈或后缀影响的变换。

### 复杂状态模拟

原 Unicorn 经验强调映射段、栈和寄存器初态。64 位 stub 经 `retf` 转到 32 位代码时，模式变化不只是入口地址变化；GPR、EFLAGS、XMM 与内存状态可能都需对应。观察目标是模式切换前后状态一致，不保留模拟器 API 或平台安装说明。

### 多阶段加载器

嵌套代码层可包含 XOR 循环、解码缓冲区与间接入口。每层应区分文件字节、解码后字节、执行权限、进入时点与输出消费者；`call rax` 只是某个样例中的层间边界。原反调试改值和执行代码转为状态及字节关系说明，不包含载荷。

### 时间侧信道

逐字符校验的提前退出可能使正确前缀对应更长时间。观察项包括候选、已知前缀、重复测量、噪声分布与路径差异；一次最快或最慢不构成判定。系统调度、缓存和 I/O 都可能产生与校验无关的延迟，因此需将时间差与逻辑路径联系。

### 未剥离信息与来源线索

调试段、编译路径和 home 目录字符串可能泄露构建环境、源文件或作者标识。存在 `.debug_*` 等节、符号和路径是不同层的证据；路径可来自第三方依赖或模板，不能仅凭一条字符串断言身份。本知识副本不保留个人密钥或平台注册信息。

### 双字节 mangle 与滚动状态

原变换每次处理两字节并更新状态，期望数据位于只读区。反关系需要保持块内字节序、每块前态、运算宽度和更新时点；不能把每个字符独立处理。可审计结果是逐块输入、输出、旧状态与新状态的对应。

### Rust serde_json 结构恢复

serde 的 Visitor、字段名、类型判断和错误路径可说明预期 JSON 结构。字段出现次序是代码与访存的线索，不必然等于 JSON 的语义顺序；只有字符串被组合或比较的证据成立时，才可推断其承载隐藏消息。

### 位置相关变换

加减位置索引的校验可按每个索引的反关系解释，前提是没有额外反馈或置换。索引从 0 还是 1 起、按字节还是字符、加减后是否截断决定结果；“位置偏移”不能只凭循环变量参与运算便确认。

### 十六进制字符串比较

输入可能先编码为 hex 再与常量比较。需要区分 hex 文本与原字节、大小写、前导零、分隔符和终止符；反解常量只给出候选原字节，真正接受的输入形式还受前处理限制。原解码命令已转为此格式关系。

## 案例经验（CTF Case Notes）

### 内嵌 ZIP 与 XOR 许可证

`EMBEDDED_ZIP`、`ENCRYPTED_MESSAGE` 与 `.rodata` 表示归档、消息及符号范围的关联。ZIP 中许可证参与消息 XOR 与输入比较，PIE 虚址仍需转换成正确文件范围。日期、比较长度、许可证字节重复规则和尾部处理是独立条件，不能用可读输出替代全部验证。

### 栈字符串与只读 blob

原样例映射 blob、XOR 还原并校验，常量 `0x9E3779B9`、`0x85EBCA6B` 和 `rol32` 指向滚动混合结构。保留 blob 边界、索引、状态初值与更新顺序；第二类位置置换和前字节反馈需要区别于单纯固定 XOR。

### 前缀摘要

每个前缀独立摘要，使已知前缀加一个候选字节可与对应目标项比较。目标数量和输入长度的差一关系只在空串摘要被包含时成立；摘要编码、截短、换行与字符域也可能保留多候选。

### 数学收敛位图

`z^3-1=0` 的 Newton 迭代可把坐标分类为像素，网格结果形成文字。关键证据包括坐标排列、目标根、迭代阈值、退出原因与图像行列。原以计数 12 分类的片段未独立证明成功收敛，文字可读性只能辅助判断布局。

### RISC-V

静态链接且 stripped 的 RISC-V ELF 可能混合压缩指令与常规指令，原 Capstone 模式名体现 RISCVC 与 RISCV64 的组合。指令长度错误会使后续地址失步；假 flag 和递增 XOR 参数也需与真正消费者对应。原 qemu 运行方式已转成架构语义观察项。

### 内核迷宫

Rust 模块以 ioctl 暴露三维尺寸、墙位、移动、状态和结果。进行中、胜利与诱饵不能只按返回值是否非零解释。DFS 的 visited、诱饵集合和重置后的状态需要分开；原方向/反方向示例存在不一致，不能复制为可靠求解器。

### 多线程通道 VM

16 个以上线程通过 futex 交换中间状态，常量可能来自系统调用返回码和其他线程。有效为零的反向约定、EPERM 返回值及通道阶段都可参与算法。BFS 模型需要完整状态与前驱，不能只记录某个线程的局部寄存器。

### CVP/LLL 受限整数系统

大系数矩阵和可打印字符边界可构成格上的受限整数问题。LLL 改善格基，不直接保证找到最近点；模 `2^32` 的 VM 第二层也不能当普通域矩阵。原第一层结果作为 AES 参数进入后续解压和 VM，层间参数与初态均应保留。

### 决策树函数混淆

约 200 个自动命名函数把多输入多项式条件展开为分支图。提取对象应含操作数、索引、位宽、比较和左右边，不能只收集比较立即数。已知格式可传播约束，词语合理性则属于先验而不是路径证明。

### Android JNI RegisterNatives

`JNI_OnLoad` 经 `RegisterNatives` 关联方法名、签名与 `fnPtr`，因此未出现标准 `Java_com_pkg_Class_method` 符号也有正常 native 入口。APK 的多 ABI `.so` 可作对照，但不同架构版本必须先确认语义同源；x86_64 只是原经验中的可读性选择。

### 多层自解密

每层少量输入与 SHA-NI 参与下一层解码，正确代码结构形成 oracle。候选间的自修改内存、BSS、栈和映射必须保持同一初态，原 JIT/fork 的价值在隔离与减少复制。吞吐数字是历史记录，不是固定工具或并发要求。

### GLSL 自修改 VM

256×256 RGBA 纹理同时表示寄存器、指令与 VRAM，STORE 改写后续绘图代码。每帧只提交末次写入的表达可丢失像素，与顺序提交的 VM 语义产生差异。结果需区分 GPU 实现的写提交模型和原指令序，不把乱码简单归因于图片损坏。

### GF(2^8) 消元

矩阵及增广向量的域加法是 XOR，域乘法使用 `0x11b` 约减，`0x1b` 是常见低位约减特征。非零主元、逆元、换行和消元决定解，零无逆元；秩不足或增广矛盾必须显式记录，不能靠示例中的错误索引得到假解。

### 单行 Python 布尔电路

海象赋值和大量分号可隐藏输入位的依赖图，`(a|b)&~(a&b)` 是 XOR。整数字节序、负值与取反的无限精度语义应与固定宽度模型区分。终值等于零是原案例谓词，求得候选后仍需复算电路。

### 滑窗 popcount

16 位窗口汉明重量差给出 `bit[i+16]=bit[i]+count[i+1]-count[i]`。首窗之外的位由递推决定，产生非二值即不成立。首窗数量由首项重量的组合数决定，不能把原“数千个候选”的经验当恒定规模。

### Ruby/Perl 多语言约束

同一文件在两种解释器中有效，`=begin/=end` 与 `=begin/=cut` 的注释边界不同，使各语言消费不同片段。有效输入应同时满足两侧条件；只读一个解释器视图会漏掉交集约束。结果需保留每个片段在两侧的语法角色。

### Verilog 与硬件状态

`always @(posedge clk)`、case 分支和移位寄存器历史共同表达隐藏条件。非阻塞赋值读取旧状态，并在时钟边沿提交，不能按顺序软件赋值解释。正确序列的依据应含复位值、每周期输入和状态，而不只是最终输出。

### 自定义 binfmt 与 RC4 平面格式

`.ko` 的 binfmt 注册把特殊文件头和解密器接入加载路径。`movabs` 立即数、256 项交换与加载器映射共同说明密码和入口，flat 数据没有 ELF 头是预期格式特征。基址来自 `vm_mmap` 等加载参数，不是由文件扩展名猜测。

### 哈希解析导入

符号名哈希、`dlopen`/`dlsym` 和间接调用可隐藏 API。静态 hash 到候选函数的对应与密码边界实参是两类证据；原“跳过哈希只截获参数”的工具选择已改成两者各自回答的问题。具体密钥、截获库和容器运行不保留。

### ELF 节头破坏

按节分析失败而程序头仍有效，说明损坏可能局限于 `e_shoff/e_shnum/e_shstrndx` 等元数据。原附加 magic 与 XOR 内容应按文件边界定位，不强依赖节表；加载段、附加区和运行可达性分别说明，不包含头部补丁命令。

### Brainfuck 逐字符静态关系

原经验关注 `,` 读入后的增量和固定算术结构。增量次数只有在确认单元初值、回绕、指针位置及比较模式后才对应期望字符；不能把所有连续 `+` 的长度直接当 ASCII。逐输入位置的单元状态与检查点才是证据。

### Brainfuck 读次数 oracle

正确前缀可能使验证器执行更多 `,`，读次数成为路径信号。候选比较需固定输入长度、EOF 行为和计数范围；最高读数只是原实例的判据，遇到循环、诱饵或缓冲差异时可能不成立。保留前缀与计数关系，不保留执行脚本。

### Brainfuck 比较惯用结构

某些固定指针/清零/转移循环组合实现相等检查。识别的目标是确认参与比较的单元和操作数，再将其对应到输入位置；只匹配短文本可能把其他算术循环误认成比较。本副本不复制执行解释器插桩代码。

### 异常共享库

setuid 程序普通运行与调试表现不同，可能来自身份与库加载条件。非标准 libc 路径、字符串差异以及 `getuid/geteuid` 到异常分支的关联共同构成证据；路径与字符串不能单独证明后门。原例保留因果链，不保留密码。

### Go 二进制

`go.buildid`、运行时符号、pclntab 和构建信息帮助恢复函数关系。Go 字符串是 `{ptr,len}` 而非 NUL 终止；`main.main`、panic、`chansend1/chanrecv1` 分别提示应用入口、异常与通道通信。元数据恢复和版本适配是能力目标，不规定 GoReSym 或插件。

### Go UUID 与 C2 身份字段

原 Go 客户端的 UUID 来自链接期 `-X` 变量值，固定长度字符串与客户端注册/API 身份有关。此经验说明编译期常量、认证材料与授权对象不能混为一谈。保留字段来源、长度、请求结构和历史观察边界，不保留替换 UUID、注册外部 C2、枚举客户端或文件的操作。

### D 语言

`_D` 前缀与 D 的独特名字修饰、模板实例和多函数变体可提示语言来源。恢复可读名称有助于分离模板噪声与应用算法，但同名前缀或某个库函数并不代表整个文件都由单一语言构建。

### Rust

`core::panicking`、符号与 panic 路径/行号可提供类型和调用关系。原资料把 Option/Result 描述成固定 0/1 判别字节，实际可能使用 niche 和版本相关布局，应以具体消费者为准。panic 路径可能来自依赖，不能直接认定为应用入口或作者身份。

### Frida 运行观察

原动态插桩经验的技术目标是观察比较实参、内存、返回值与调用关系，而非依赖特定启动命令。改变校验函数或反调试返回值会改变程序语义，记录时需区分自然执行证据与干预后结果；本页不包含 hook 代码。

### Firebase Cloud Functions 与客户端校验

原 Android 案例涉及登录后构造的 UID、值和时间戳，以及客户端 QR/支付流程与云端函数的关系。知识重点是身份、业务授权和参数来源是否在服务端独立绑定；客户端路径是否出现不能代替服务端授权证据。不保留直接调用函数或绕过支付的步骤、请求和载荷。

### angr 与路径约束

符号执行把路径分支与输入限制汇成约束，目标、避开位置、字符域和已知前缀决定搜索范围。密码、I/O 或复杂库函数的抽象可能减少路径膨胀，也可能丢失真实语义；应注明抽象内容、返回约定与候选的回代结果，不保留框架 API。

### Qiling 与系统环境

跨平台模拟同时涉及 CPU、系统调用、文件系统和环境。原资料“默认绕过所有反调试”的表述过强：缺少真实调试器只消除部分线索，环境、时间、映射和 API 差异仍可能触发检查。结果应注明模拟边界与缺失状态，不把模拟成功当真实环境等价证明。

### VMProtect/Themida

虚拟化入口、handler 表和大规模间接分派可指向 VMProtect 类结构；输入相关运算轨迹能提供局部语义，完整去虚拟化则需要更全面状态。Themida 的原入口与内存解包结果是另一层问题，不能把“可见 OEP”当所有导入和自修改状态均已恢复。

### 二进制差异

原始/修改版本之间的函数匹配、控制流差异和常量差异有助于定位新增逻辑。编译器、优化和链接布局变化可能造成非语义差异；结果需要给出匹配依据与置信度，不能把所有未匹配函数都标成漏洞或后门。

### 高级调试与回放

寄存器上下文、映射、内存搜索和栈指针解引用提供程序状态快照；反向回放可追溯某值如何形成。多线程与外部 I/O 的可重放性限制需注明。原 pwndbg/GEF/rr 和脚本的名称保留为历史背景，不包含调用命令或固定工作阶段。

### macOS/iOS

Mach-O load commands、Objective-C 类型信息和 Swift 符号分别说明装载、消息派发和语言结构。iOS 应用的加密状态、签名与运行环境影响可读字节和启动行为；重签名不是语义等价证明。原解密、越狱检测干预与签名命令转为这些观察项，不写执行步骤。

### 嵌入式/IoT

固件容器、压缩层和 SquashFS/JFFS2/UBI 等文件系统需要按偏移与边界分层解释。UART/JTAG/SPI 是原经验里的获取渠道，固件字节、芯片、内存映射与应用逻辑仍是不同证据层。模拟是否可用取决于外设和环境，不保证主机上直接等价运行。

### 内核驱动

Linux `.ko` 的 `file_operations`、ioctl、`copy_from_user/copy_to_user` 说明用户/内核边界；Windows `.sys` 的 `DriverEntry`、设备创建与 IRP handler 说明分派关系。eBPF 转译字节码属于另一表示。重点保留输入缓冲区、长度、状态码与权限，不包含模块启动或内核调试命令。

### Swift/Kotlin

Swift 的协议 witness table、`__swift5_*` 与名字修饰辅助恢复派发和类型；Kotlin/JVM 协程常在 `invokeSuspend` 中形成状态机，Kotlin/Native 则使用 LLVM 生成本机代码。类 C++ 外观不能替代语言与运行时证据。

### INT3 与崩溃快照 oracle

原案例以 INT3 后的 core 状态观察复杂变换的中间值。快照只有在输入、时点、线程与映射对应时才有判别意义；core 中的可读字符串未必就是比较值。保留中间值和候选的关系，不保留补丁、core 配置或逐候选运行代码。

### 信号 handler 链 oracle

每字符验证成功后安装下一 handler，注册事件可能成为当前字符通过的信号。要证明此关系，需要对应输入索引、handler 身份、注册时点和失败路径；“出现注册”不自动等于整个输入正确。原 LD_PRELOAD 程序已转为事件与状态知识。

### 字体连字

GSUB 把多 glyph 输入替换成一个 glyph，cmap 和 lookup 次序决定字符如何显示。隐藏消息的证据不是字体文件名，而是输入序列、Component、LigGlyph 与可见字形的对应；多步替换和非 Unicode glyph 名称会产生歧义。

### 指令计数密码状态

递增寄存器参与 XOR、旋转和乘法时，算法依赖实际指令路径。前面分支改变后面计数，逐位置判据必须包含正确前缀状态。只保留每字节数学变换而省略计数更新会丢失算法；原模拟器运行代码不复制。

### BWT 逆变换

无终止符或 primary index 时，重建旋转表通常产生多个候选。二进制表示、XOR 轮关系和格式限制可辅助选择，但逆操作顺序必须与正向组合相反；周期输入还可能产生重复行。结果应保留轮次与选择依据。

### FRACTRAN

FRACTRAN 按列表顺序选取使当前整数乘积仍为整数的分数，素因数指数可编码状态与 I/O。原“交换分子分母后反跑”只在可逆分支与原顺序条件成立时有效，不能当一般 FRACTRAN 的无歧义逆算法。前驱多解和选择顺序需要保留。

### 仅 opcode 的轨迹

没有操作数数据的轨迹仍可通过分支路径泄露比较关系，排序算法尤其可能表达元素的偏序。重复片段与基本块边界应解释为结构化执行关系；去重不能删除循环次数、稳定性或先后信息，否则可能丢失重建依据。

### 线程竞态与 signed overflow

技能状态在检查后、伤害使用前变化，说明二者未使用一致快照。`cdqe` 把 `0xFFFFFFFF` 扩展为 `-1`，机器级 HP 减法产生符号位翻转；需要对应真实指令及后续比较，不把源级有符号溢出泛化为稳定行为。本页不含竞态触发脚本。

### ESP32/Xtensa

原 ROM linker script 提供地址到函数的名称映射，可辅助识别 HTTP handler 和全局状态检查。映射需与芯片和 ROM 版本匹配，固件加载地址与 ROM 地址应分开；公开例程只是结构参照，不是应用算法相同的证明。

### VM 提升为 LLVM IR

将 opcode 语义表示为中间表示后，内联、常量折叠和死代码消除可显示更紧凑算法。原约 1300 行到约 150 行是案例规模。提升必须保持寄存器宽度、内存别名、分支和异常语义，优化后的简洁外观本身不证明等价。

### SIGFPE 隐式控制流

算术异常 handler 可承载真实逻辑，静态基本块图可能漏掉信号边。某些候选使更多 SIGFPE 出现，计数便成为原案例的路径判据；计数必须和输入位置及处理器链对应，不能把所有异常多的候选当有效输入。

### 批量 crackme 算术

同构文件的 CMP 立即数、add/sub 运算链与样例顺序是抽取目标。反推从目标开始按逆序撤销运算，保持位宽并正向复核；其他分支和同名寄存器操作不能混入。原命令管道和正则运行代码不保留。

### Android DEX 运行时修改

native 库可能读取进程映射、改变页权限并 XOR 改写 Dalvik 字节码，因此静态 APK 与运行时 DEX 不同。需要对应 native 中的偏移、范围、参数和目标 DEX 方法，区分代码尚未修改与已修改的时点；不保留补丁脚本或具体密钥。

### fork/pipe 与死分支

父写子读的 pipe 关系解释数据来源，子进程继续执行与父进程退出不是矛盾。看似恒假的比较需结合赋值和 IPC 判断；原改变条件后的隐藏路径属于干预结果。报告保留两种路径的边界，不复制二进制字节补丁。

## Web/CTF 认证案例

### 签名 cookie 的用途与密钥复用

原教学案例中，公开 access/invite 类 token 与服务端签名材料发生复用，入口 cookie 和管理会话 cookie 虽名字不同，却缺乏独立的秘密与用途绑定。知识对象是 cookie 的两段结构、base64url 编码、紧凑 JSON 序列化、HMAC-SHA256 覆盖的精确字节以及服务端实际读取的授权字段；签名算法本身并不能纠正公开密钥材料的选择。

原记录还说明不同 JSON 形状并非等价：人类理解的 role/access 语义不代表后端消费相同字段。这里保留“字段名、类型与序列化都是协议的一部分”的判断，不复制管理授权 payload、伪造 token/cookie 代码、原 token 或密钥。原服务地址不构成本页的操作目标。

历史证据包括未授权响应与授权响应的差异、其他只读管理数据的可见性，以及解析错误导致 500 而不是 401。后者表明 cookie 类型/解析假设脆弱，不能据此单独推断整个应用框架或完整认证链。原 JSON-cookie 特殊输入不作为可执行样例保留。

根因表达应区分公开入口标记、服务端秘密、签名方案、会话类型和权限绑定。原修复知识包括服务端独占签名秘密、学生/管理员材料隔离、管理员身份的服务端会话、严格类型检查和统一失败响应；不扩展密码猜测、用户枚举或外部验证操作。

## 分析前预判：文件伪装与名字欺骗

### 文件后缀不可信

扩展名只是一项标签，magic、头字段、段结构和消费者决定真实类型。原例包括 `.sh` 实为 ELF、`.txt` 实为 PE/ELF、`.jpg/.png` 实为可执行或归档、`.dll` 为托管程序集、`.so` 为加密内容以及无后缀文件。ELF 的 `7f 45 4c 46` 是格式线索，但仍需核对架构、端序与范围，避免只凭四字节作完整判断。

### 文件名不可信

DriverLoader、SystemService、Updater、Helper、lib*.so 等名称可能与实际行为不同。驱动加载、进程注入、下载、服务和辅助程序需要代码证据分别支持；缺少某个驱动加载 API 是反证线索，不能独立证明不存在其他加载路径。名称不是结论，真实调用、目标对象与数据流才是判断依据。

### 静态不足时的补充证据

解码/解压需要对应运行时明文与消费者，大量间接调用需要目标分辨，反调试需要条件到分支的关联，跨架构代码需要确认模式与环境，未知协议需要消息字段与状态。原跟踪、模拟、抓包命令已转换为这些观察目标，不规定动态执行是所有情况的强制阶段，也不运行原样本。

### 进程注入与保护壳模式

原记录以 LinYuDriverLoader 一类名字为例，实际线索涉及 ptrace、`/proc/<pid>/mem`、映射、加密代码和 hook；其他检查包括 TracerPid、时间差与自追踪。应把宿主加载器、目标进程内存、解码层与保护检查分别归因，区分“存在能力”与“实际发生”。原“通常不是驱动”的经验不能替代对具体样本的证明；本页保留观察关系，不包含注入载荷、干预程序或启动步骤。
