# 逆向工程基础：对象、证据与判断

来源：skills/reverse-engineering/SKILL.md

本文承接原入口文档的技术知识。源中的平台注册字段、工具安装说明、自动执行要求、固定 agent 阶段和跨模块强制路由不构成知识正文；其技术含义整理为分析对象、观察项、判断依据与证据结构。

## 适用对象与问题边界

逆向工程关心编译、混淆、压缩、虚拟化后的实现如何工作。对象包括本机二进制、APK、WASM、固件、自定义 VM、字节码、多阶段加载器、反调试与反分析逻辑。关键问题是输入如何进入程序、经过什么变换、状态如何传播、什么条件决定输出。

已知缺陷后的堆利用、ROP 或内核利用属于漏洞利用问题；删除文件、PCAP 和磁盘痕迹属于取证问题；纯 Web 业务、独立密码数学题、模型攻击和解释器沙箱也各有不同知识重心。交叉场景可按当前阻碍区分：若阻碍仍是恢复实现，就仍需逆向；若实现已经明确，则问题转向相应领域。此处只说明边界，不规定切换某个 agent 或调用其他技能。

## 分析前提与材料组织

原文以本地 CTF、crackme、培训目标和隔离样本为常见背景。这个背景只是材料语境，不能从文档推定实际目标的授权或运行条件。研究记录可以区分原始文件、分析副本、静态证据与运行时证据；记录样本身份、架构、格式和修改范围有助于防止把不同版本的结果混在一起。

静态材料包括文件头、段节表、字符串、导入导出、符号、交叉引用与控制流。运行时材料包括比较操作数、调用参数、返回值、系统调用、寄存器和内存状态。跨架构语义恢复需要正确的指令集、位宽、端序、ABI、内存布局与环境语义，而不是某个固定软件组合。

## 低成本线索与初始画像

可见字符串中的 `flag{`、`CTF{`、密码提示、成功或失败消息往往能缩小范围，但字符串存在不证明它参与最终校验。文件魔数和文件头用于确认真实格式与架构，不能只依据扩展名。安全属性与加载方式描述运行环境；PIE、地址随机化和可执行内存布局会影响地址解释。

库函数比较、文件读写与系统调用轨迹有时直接暴露输入格式或预期值。需要区分“观察到期望值”和“完整理解生成逻辑”：前者可解释局部比较，后者才支持推广到其他输入。修改执行逻辑之前，控制流、依赖数据和错误分支的关系应在知识记录中可见。

## 问题建模与证据维度

不同观察方式回答不同问题：

| 目标 | 关注内容 | 可观察结果 |
|---|---|---|
| 字符串与导入信息归类 | URL、路径、算法常量、错误消息、API 家族 | 目标功能假说及其交叉引用 |
| 比较逻辑理解 | strcmp/memcmp 的双方、长度、返回值、调用者 | 输入与目标的真实关系 |
| 符号约束 | 输入位宽、字符域、成功状态、失败状态 | 满足路径条件的候选及验证结果 |
| 跨架构或环境语义恢复 | 寄存器、映射、栈、系统调用与 ABI | 可解释的指令状态转移 |
| 多种反编译表示对照 | 分支、类型、符号性、调用约定 | 对工具误判或歧义的定位 |
| 重复变换整理 | 相同函数、相同校验族、重复状态更新 | 可复用的算法模型与边界条件 |

这些维度可以按问题组合，不构成固定执行顺序。

## 内存中计算结果与最终比较

程序可能在运行时先计算正确答案，再与用户输入比较。最终比较点附近的内存能够包含已经解密或生成的目标。关键证据是：比较地址、调用点、双方缓冲区、比较长度、所处阶段，以及这些值分别来自输入还是程序内部。

原文的 x86-64 示例关注某个参数寄存器中的字符串，但参数位置取决于平台 ABI 与具体比较指令，不能把单一寄存器等同于所有目标的答案。正确长度输入与任意内容输入也可能走不同路径，记录中需区分长度门槛和内容门槛。

## 诱饵与多级校验

多个比较目标、相似的成功消息或先出现的明文标记可能是诱饵。判断依据是该分支是否能到达实际成功状态、后续是否还有校验、结果是否被覆盖，以及与最终输出的依赖关系。早期比较的匹配不一定意味着任务完成；最终比较通常更接近真实接受条件，但也需要完整控制流证据。

## PIE 与地址关系

PIE 二进制的加载基址可变化，静态地址与运行时地址不能直接混用。函数内偏移或模块相对地址能够稳定描述同一位置：

```text
运行时地址 = 当前模块加载基址 + 模块相对偏移
函数内位置 = 当前函数运行时地址 + 函数内偏移
```

记录地址时保留基址、偏移、模块身份和位宽，可以区分错误定位与错误语义判断。

## 比较方向：两类相反的问题

1. `transform(input) == stored_target`：目标数据位于变换输出域，恢复输入需要理解或逆转变换。
2. `transform(stored_target) == input`：变换作用于内置数据，候选输入就是其变换结果。

两者可能显示相似的反编译代码。区分依据是数据来源与写入方向，而不是变量名。把第二类误当第一类会造成不必要的逆运算或错误求解。

## 常见加密与编码模式

- 单字节 XOR 的候选空间为 256；已知明文可约束密钥。
- 重复密钥 XOR 常与位置索引叠加，如 `key[i mod L] XOR i` 或只使用 `i` 的低 8 位。
- RC4 常见硬编码或运行时生成的密钥；识别时结合 256 字节状态表和交换过程。
- 自定义置换与 XOR 的组合需要保留两者次序，不能交换处理。
- `flag{`、`CTF{` 等已知前缀只是案例先验，不能替代真实格式证据。

## 证据与报告结构

一份可复核的技术记录包含目标身份与边界、格式与架构、入口与核心路径、输入输出关系、算法与常量、关键比较或状态证据、诱饵判断、假说和反例、验证结果及剩余不确定性。复现的重点是这些证据与推理之间的对应关系，不是工具路径、安装过程或是否完成预设 agent 阶段。
