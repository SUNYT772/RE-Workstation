# 逆向案例：数据布局、隐式控制流与加载边界

来源：skills/reverse-engineering/patterns-ctf.md

## 阅读定位

本页保留原资料第一组十五个案例。赛事、年份、样例地址和规模均为原记录的背景，不构成对其他二进制的默认假设。每节分别说明识别证据、技术关系、结果表达与歧义；原运行脚本、编译指令、预加载库、部署步骤、具体密钥与载荷不纳入知识副本。

## 隐藏模拟器指令与密码边界（0xFun 2026）

### 识别与结构

CHIP-8 模拟器的常规指令分派中出现非标准 `FxFF` 分支，流向拼写为 `superChipRendrer()` 的函数。函数名像显示处理，但其内部实际出现 AES-256-CBC 相关逻辑。入口的意义由指令掩码、分派条件与函数体共同决定，不能根据 renderer 的名字排除密码功能。

### 参数关系与证据

原案例的密码参数来自二进制常量；需要区分 256 位密钥、CBC 的块长与 IV、输入长度、输出缓冲区及填充处理。密码库边界可作为“调用时实际使用什么参数”的证据位置，重点是实参内容与调用前后的数据关系，而不是某一种截获库。静态常量只能证明存在，调用位置与实参流才能证明参与该次解密。

### 结果与局限

可审计结果包括非标准 opcode 到函数的控制流、密码模式、参数各自来源、密文与明文长度及后续消费者。原预加载截获代码与编译/启动方式已转为这些观察目标；不保留具体密钥字面量。

## Spectre-RSB SPN：从实现噪声中辨认参数（0xFun 2026）

### 识别与结构

原实现以缓存侧信道承载 S-box 选择，表面看似需要重建微架构行为。但 S-box、置换和轮参数已存在于静态数据区，密码抽象与运行载体可以分开理解。原记录包含 8 个 S-box，每个表有 256 个输入项，每个输入的 8 个输出位由相应布局表达。

### 数据布局与模型

样例中 `0x340` 与 `0x100` 分别对应位值 1 与位值 0 的标记；这些数值是该布局的编码标签，不是通用缓存阈值。按原输入序和位序重组后，得到字节替换表；再与 64 字节置换和 8 轮轮参数连接。置换表的方向必须说明是“输出位置取输入”还是“输入移到输出”，解密所需的是相应逆映射。

### 结果与局限

结果应列出各段数据的边界、S-box 的输入输出宽度、置换方向、轮数和各轮参数来源。原代码中省略切片的片段不能当完整密码实现；本页保留其布局知识，不复制轮密钥或侧信道调用程序。静态参数足够的结论只适用于这个案例，不能泛化为所有 Spectre 实现。

## 图像 XOR 掩码与平滑性判据（VuwCTF 2025）

### 识别与模型

图像被分成三角区域，各区采用位置相关的 XOR 变换。原位置项为 `(mask*x-y)&0xff`，`mask` 在 0–255 中取值。单区候选数量有限，但候选优劣并非由密码学完整性直接判定，而是借助自然图像的局部连续性。

### 评分与边界

一种原有评分是相邻像素差绝对值总和的负数：差异越小，得分越高。横向、纵向邻接、区域边缘是否计入，以及灰度还是逐通道计算，都影响评分。区域边界混入另一套变换时会产生假惩罚，因此区域掩码与坐标原点必须与原变换一致。

### 结果表达

保留每区候选得分、首选与次选的差距、还原前后边界连续性以及人工可辨结构。平滑性是图像先验；纹理、文字边缘、噪声或本来就不平滑的图像可能使错误候选领先，不能仅凭最高分声明唯一正确。

## 数据段中的运行时代码（VuwCTF 2025）

### 识别与结构

样例把数据区字节搬入具有执行权限的内存映射，再经间接控制转移进入。部分内容有三字节循环 XOR 编码，因此文件中看似无效的数据可能是运行时代码，而最初反汇编的可执行节只包含搬运和解码器。

### 地址、权限与时点

需要对应源文件范围、目标映射基址、映射大小、权限、解码前后字节及间接入口。代码的架构模式和入口偏移也属于解码后解释的一部分。RWX 映射本身是观察项，不能单独证明恶意；搬运、解码和转移构成更完整的行为链。

### 结果表达

按“容器数据 → 解码关系 → 内存代码 → 消费者”记录层次，说明何时字节才具有指令语义。本页不包含样例 shellcode、载荷构造或运行调用代码。

## 递归 execve 与减法递推（VuwCTF 2025）

### 识别与模型

程序重复自执行，每一代从参数中减去常量，直到命中基例。单次进程轨迹只能看到一个递推步；跨代参数才表明完整计算。若每步减少 `M`，经历 `N` 步后到达余量 `r`，在没有溢出、截断或其他分支时，原值关系为 `N*M+r`。

### 证据与局限

应区分执行代次、父子/替换关系、字符串到整数转换、参数宽度、符号和终止条件。`execve` 是进程映像替换，不等同于普通函数递归；环境变量和参数重新解析可能改变语义。只有递推步和基例都成立，反推公式才有效。

## 无跨字节扩散的块变换（UTCTF 2024 PES-128）

### 差分观察

虽然外观是块密码，改变一个输入字节只改变对应的一个输出字节。这说明原案例缺少跨字节扩散，可把相关位置表示为小域映射，而不必先还原整个密码名称对应的复杂结构。

### 逆映射

对每个位置，映射域最多为 256 个字节。若不同位置共用同一映射，还需有位置等价证据；否则应分别建表。输出到输入的逆表可能包含多个候选，映射未必单射。多个输入落到同一输出时，长度、字符域和其他检查只能进一步筛选，不能直接取第一个结果并宣称唯一。

### 结果表达

记录单字节扰动的输入输出位置、映射覆盖率、碰撞以及其他候选约束。原“逐字节可逆”的经验已保留为带前提的判据。

## Newton 收敛分类与位图（EHAX 2026 Compute It）

### 识别与结构

二进制对坐标对进行 Newton 迭代，分类结果按网格排列后形成字形。原目标方程为 `z^3-1=0`；2600 个点对应样例的 130×20 布局，文字还可能体现每字约 5 像素的高度结构。这是分类器输出，不一定是逐字符密码校验。

### 原算法关系

```text
f_real = x³ - 3*x*y² - 1
f_imag = 3*x²*y - y³
J_rr = 3*(x²-y²)
J_ri = 6*x*y
det = J_rr² + J_ri²
x_next = x - (f_real*J_rr + f_imag*J_ri)/det
y_next = y - (f_imag*J_rr - f_real*J_ri)/det
```

原记录的最大迭代数为 50，`det<1e-9` 时中止，接近 `(1,0)` 的阈值为 `1e-6`，目标分类使用 12 轮。更新时实部与虚部应取同一轮旧状态；若原语言逐句赋值改变依赖，则要以实际实现为准。

### 证据与歧义

原示例最终只判断 `count==12`，并未独立保证确已收敛到指定根；因此“第 12 轮退出”和“第 12 轮成功收敛”不可直接合并。结果应保留点序、行列顺序、迭代次数、退出原因和图像极性，区分数学模型与原代码条件。

## PE 中 XOR 位图与文字渲染（srdnlenCTF 2026）

### 数据结构

样例把输入渲染成文字，与 `.rdata` 中编码后的 DIB 像素比较。源记录的文件偏移为 `0xC3620`，数据大小 `0x15F90`，等于 `450*50*4` 字节；通道按 BGRA 解释。这组数字是案例定位信息，不是任意 PE 的固定位置。

### 图像解释与证据

除字节变换外，还要确认宽高、每像素位数、通道顺序、行方向、stride、透明度与字体栅格差异。文字识别只是辅助观察；字形近似、反色、大小写、标点和字体抗锯齿都可能造成歧义。最终应区分人眼/OCR 候选与像素比较真正接受的字符序列。

### 结果表达

保留源数据范围、DIB 参数、可视结果与字符域判断。本页不保留具体 XOR 密钥或 OCR 程序调用。

## 两阶段加载器：RC4 门控与 VM 约束（srdnlenCTF 2026 Cornflake）

### 层次与边界

第一层根据用户名相关条件执行 RC4 处理，后续字节码来自原案例的 C2 第二阶段；第二层以约 15–20 个 opcode 的 VM 验证输入。网络来源是历史样本结构，本知识页不包含下载、连接或执行第二阶段的步骤。

### RC4 与 VM 的知识模型

RC4 的 KSA 对 256 项置换状态按参数序列重排，PRGA 持续交换并生成字节流，密文与流做 XOR。算法参数可记作 `K`，不保留样例密钥和密文字面量。VM 层应保留指令宽度、寄存器、内存、分支、比较及输入映射；线性运算与终值比较共同构成约束系统，不能把 opcode 名称当作完整语义。

### 状态歧义

原资料将某些未初始化内存当作全零，此判断只在具体分配、装载或运行证据支持时成立。栈、堆、匿名映射和显式清零的来源不同；无法证明的初值应作为未知状态保留。报告需注明第一层门控、阶段边界和第二层约束分别由哪些证据支持。

## 内核模块三维迷宫（DiceCTF 2026 Explorer）

### 协议字段

Rust 内核模块通过设备 ioctl 暴露迷宫。原状态编码为 0=进行中、1=胜利、2=诱饵。输出不是“存在可读数据就成功”，而取决于状态语义。

| ioctl 标识 | 原记录含义 | 约束或输出 |
|---|---|---|
| `0x80046481`–`0x80046483` | 三轴尺寸 | 样例各轴 8–16 |
| `0x80046485` | 状态 | 0、1、2 的区别 |
| `0x80046486` | 墙位字段 | 六方向的可通行关系 |
| `0x80406487` | 结果缓冲区 | 64 字节，仅状态 1 有效 |
| `0x40046488` | 移动 | 方向号 0–5 |
| `0x6489` | 重置 | 重置后状态与位置需辨认 |

### 图模型与状态

位置 `(x,y,z)`、墙位、方向和终态可形成有限图。深度优先搜索中的 visited 表示已访问位置；诱饵集合 bad 具有不同含义，需要区分单次探索状态和跨重置保留的知识。回溯依赖反方向与实际移动结果一致，而不是凭方向编号推断。

### 原示例歧义

原坐标增量按 `+x,-x,+y,-y,+z,-z` 排列，但反向表的前四项与这一排列不一致；墙位注释和判断也有相反表述。知识副本保留问题和检验依据，不复制该程序为可用实现。原 raw syscall 求解器、上传部署和 initramfs 操作均转写为协议与状态观察项。

## 多线程 VM 与 futex 通道（DiceCTF 2026 locked-in）

### 数据流

原案例约 16 个线程处理 30 字符输入，链路可表示为“输入 → XOR → 变换 → base-4 状态机 → 最终判定”。线程间通过 futex 通道交换数据，因此单线程函数局部的常量可能来自其他线程、线程标识或系统调用返回值。

### 同步语义

原记录的有效返回值为 0、阻塞或失败为非零，不能把非零统一解读为成功。对未持有的互斥对象进行 `unlock_pi` 可能返回 `EPERM=1`；若返回值参与后续运算，它便是算法输入的一部分，而非可忽略噪声。

### 搜索模型与结果

状态需包含通道值、线程阶段和 base-4 自动机状态。原分析从位置 28 向 5 反向考虑中段，再结合固定前后缀；BFS 的节点等价条件和回溯前驱必须保持充分状态。报告应体现跨线程来源、返回码、逆向位置顺序与最终字符约束，而不是把线程调度顺序写成固定 agent 阶段。

## 共享库异常与字符串差异（Hack.lu 2012 Zombie Lockbox）

### 识别证据

同一 setuid 程序在普通条件与调试条件下行为不同，异常库路径是线索。原记录对比了 `/lib/libc/libc.so.6` 与 `/lib32/libc.so.6`，通过字符串差异和函数分支定位异常内容。

### 因果判断

需要把实际加载对象、库版本、`puts`/`strcmp` 的分支、`getuid`/`geteuid` 差异和运行时替换目标对应起来。字符串新增本身不是恶意证明；路径不同也可能来自兼容环境。真正证据是身份/条件改变与异常函数行为的关联。

### 结果表达

保留正常库与异常库的对照、差异所在对象、触发条件与可见输出；不保留密码字面量或替换库执行代码。原案例不支持“所有非标准 libc 路径均是后门”的泛化。

## 自定义 binfmt 与 RC4 平面二进制（BSidesSF 2026）

### 加载结构

`.ko` 中的 `register_binfmt`、`unregister_binfmt` 与 `linux_binfmt.load_binary` 表示自定义格式装载边界。文件头含格式 magic 和加密负载，后者解密后可能是 flat binary，没有 ELF 头并不意味着无代码。

### 参数与映射

原案例密码参数的一部分位于 `movabs` 立即数中；RC4 的 256 项交换结构可与这些实参交叉印证。`vm_mmap`、`vm_brk` 的地址和范围决定代码被如何放入地址空间，正确基址来自加载器，而不是由 flat 文件猜出。

### 结果表达

记录头长度、magic、加密范围、算法识别依据、映射权限、入口偏移与基址关系。样例密钥、运行内核模块和启动负载的代码不保留。

## 哈希导入与无显式导入的勒索样本（BSidesSF 2026）

### 解析链

缺少可见导入不等于没有外部 API：`dlopen`/`dlsym`、符号名哈希、间接调用共同构成动态解析链。原样例还用 RC4 隐藏 RSA 公钥、路径及其他参数，静态字符串很少只是编码结果。

### 哈希特征

| 形式 | 原记录识别要点 |
|---|---|
| SipHash | 两个 64 位种子及相应轮结构；种子不在本副本展开 |
| DJB2 | 常见初值 5381，乘 33 与字符累计关系 |
| FNV | 原案例关注 64 位初始常量 `0xcbf29ce484222325` 与乘/XOR 结构 |
| ROR13 | `ror32(hash,13)+c`，需确认大小写、终止符与位宽 |

### 静态与运行证据

由候选符号计算的哈希与查找表对应，可以解释解析结果；密码函数边界的最终参数则解释该次操作。两者是不同层的证据，不能互相代替。结果包括 API 映射、参数来源、数据流和失败原因。本页不包含截获库、容器启动、AES 参数文件读取代码或具体密钥。

## ELF 节头损坏与装载视角（BSidesSF 2026 stubborn-elf）

### 结构关系

原样例有意损坏节头，使按节解析的程序出错，但程序头仍能描述装载。对于这里讨论的可执行 ELF，`PT_LOAD` 的文件偏移、虚址、文件大小、内存大小与权限是运行映射的重要依据；节头主要承担链接、调试和分析元数据作用，通常不是执行时的必需表。

### 故障定位

`e_shoff`、`e_shnum`、`e_shstrndx` 异常可能破坏节名和范围解析。需要把格式标识、程序头范围、文件长度与实际装载行为分别列出，而不能因为一个分析器失败就认定文件不可执行。样例还在损坏节后附加 magic 标记和 XOR 编码内容；该附加区与加载段是否重叠应独立说明。

### 结果与保真

保留节表与程序头不一致的证据、可恢复的数据范围、附加标记和解码关系。原二进制头修改、字节补丁和命令已转为“以装载视角解释损坏元数据”的知识，不写修补脚本，也不保留具体 XOR 密钥。
