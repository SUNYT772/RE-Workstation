# 高阶方法：虚拟化、差异与语义简化

来源：skills/reverse-engineering/tools-advanced.md

本页对应商业保护、二进制差异、反混淆 IR、动态符号状态、观察条件、格式修复与约束提取。历史工具名称作为方法和格式的索引，不定义安装、云服务调用或固定 agent 顺序。

## VMProtect

### 识别

VMProtect 把 x86/x64 逻辑表示为自定义字节码与解释器。`.vmp0`、`.vmp1`、相关字符串、部分区域熵高于 7.5、保存大量寄存器的入口、间接分发表和嵌入 handler 的检测逻辑都是原文线索。节名或高熵不能单独定性；不同构建可变异 handler，使同一 opcode 的地址和形态不同。

### 语义结构

VM 入口保存主机寄存器，handler 表通过间接控制流连接。vAdd/vSub/vMul/vXor/vNot 属于算术；vPush/vPop 属于虚拟栈；vLoad/vStore 属于虚拟内存；vJmp/vJcc 处理控制流；vRet 恢复主机状态。恢复对象包括虚拟 PC、寄存器或栈、操作数宽度、分发规则和退出条件。

### 历史项目与表示

VMPAttack 对应 handler 识别，NoVmp/VTIL 对应提升与去虚拟化，其他社区资料对应 handler 与 IL 简化。完整去虚拟化并非唯一知识目标；输入在 VM 内参与的密码、比较和变换也能形成局部但可解释的模型。

### 案例观察

分发事件可记录 handler 索引、opcode、操作数、虚拟栈和主机栈。原例假定索引位于 RAX，这不是通用布局。局部轨迹只支持经过的输入和路径，不能冒充整个 VM 指令集恢复。

## Themida / WinLicense

### 识别

`.themida`、`.winlice` 节、代码变异、虚拟化与压缩组合，以及重反调试是原文特征。内核级检查或驱动存在是需要证据的行为，不由保护器名称自动推定。

### 解包后的结构

原流程承载的技术对象是解包时点、OEP、已展开内存、IAT 和文件头。正确的恢复产物应具有映射一致的入口、有效导入、代码/数据边界和可解释的调用关系。ScyllaHide、Scylla 的名称保留为历史背景，不保留预设、菜单和运行步骤。

## 二进制差异

### BinDiff / BinExport

函数匹配、未匹配函数、指令变化和每对函数 0–1 相似度是原文核心产物。BinExport2 是交换格式名；“高相似”并不保证行为等价，编译选项、内联、链接和符号变化都会影响匹配。

### Diaphora

原资料把它作为另一种函数和结构匹配表示。原版与修补版之间的新增、删除、边界检查或错误分支差异可以缩小问题范围；漏洞、隐藏功能与正常重构需要由上下文区分。

## 反混淆的表示层

完整变种资料见 [OLLVM 专题](references/ollvm-deobfuscation.md)。

### d810-ng：规则与 SMT

原记录涵盖 Z3 验证的 MBA 等价、Pred0/PredFF/PredSetz/PredSetnz 谓词、22 条常量折叠规则、Hacker's Delight 位运算、Hodur 专用表达式。控制流形态包括 O-LLVM 的 switch/if-chain、Tigress 的 m_jtbl 与 m_ijmp、Hodur 的 while(1)+jnz state、Approov 的 0xF6000–0xF6FFF 状态常量。规则名是历史表示，实际判断依赖状态变量和真实边。

### obpo：microcode、切片与混合执行

原资料描述在 Hex-Rays microcode 上进行数据流跟踪、程序切片和 concolic 推理，改变的是反编译表示。其历史覆盖包括 IDA 7.5–7.7 与 ARM/ARM64/x86/x64/PPC/MIPS，且原架构涉及目标函数上传。这里保留技术和数据边界，不保留访问要求。

### Miasm 型多层恢复

ollvm-unflattener 代表 IR 符号执行及按调用关系 BFS 归并，原覆盖为 x86/x64、Windows/Linux。核心结果是真实状态转移和边，而不是“纯脚本”或 GUI 的优劣。

### Android native 表示

ollvm-breaker 的原案例包含 libvdog.so，关联 JNI_OnLoad、包名与附着检测逻辑。识别特定函数的意义是连接 Android 生命周期与 native 控制流。

### BR 间接分支

DeObfBR 对应 Goron/Arkari 风格间接分支。源中“只读数据段”经验转为数据不可变性假设：若目标依赖的数据确实不再变化，可使间接目标更容易静态解释；若程序运行时会更新它，错误假设就会损害语义。

### ARM64 具体状态

deollvm/Unicorn 代表以具体寄存器与内存状态解释 ARM64 dispatcher。状态、外部依赖和未执行分支的覆盖仍需单独记录。

### GOOMBA / P-Code

原主题是 P-Code 层的 MBA 简化和已知混淆形态匹配。表达式等价、位宽和副作用必须保留，格式清晰不等于证明正确。

### Miasm IR

输入文件、架构、入口和反汇编基本块产生 IR CFG；符号状态沿 IR 传播，可用于表达式树简化、复杂算术和数据流。错误入口、错误指令边界和遗漏调用语义都能产生错误 IR。

## OS 层模拟（历史名称 Qiling）

CPU 外的 syscall、文件、注册表和库加载构成运行环境。原文包括 Linux/Windows/macOS/Android/UEFI 与 ARM/MIPS/RISC-V 的跨架构问题。无调试器痕迹不保证所有检测都失效；原 ptrace、IsDebuggerPresent 或特定地址返回值示例仅说明检测分支依赖的状态。已有轨迹与原始代码未修改也不意味着外部环境完全相同。

## 动态符号执行（历史名称 Triton）

具体指令流、符号输入、污点关系与 AST 简化可以同时存在。原例以 32 字节输入在比较点提取路径条件并求模型；模型变量应映射回输入索引，而不是只按名字排序。单路径 DSE 的状态数量通常较少，但覆盖与当前执行流相关。

| 维度 | 具体轨迹驱动的 DSE | 多路径符号探索 |
|---|---|---|
| 执行依据 | 已有具体路径及符号数据 | 符号分支和状态集合 |
| 常见代价 | 当前路径语义与依赖 | 多状态数量与路径爆炸 |
| 知识重心 | 单路径反混淆、污点和表达式 | 多路径可达性、候选输入 |
| 局限 | 未走到的路径缺乏证据 | 抽象、环境与状态扩张 |

源文的软件速度比较是经验背景，不是普遍性能结论。

## 路径状态与 EVM（历史名称 Manticore）

成功状态可求出输入符号模型，失败状态可从候选集中区分。输入长度、成功/失败位置和状态副作用构成知识对象。EVM/智能合约与本机二进制有不同环境语义，不能因同属符号执行而混用。

## 联合视图（历史名称 Rizin / Cutter）

函数列表、反汇编、CFG、十六进制与调试状态可以共用地址与样本身份。脚本控制台、图形界面、开源属性属于历史产品背景；有效产物仍是可相互核对的结构和状态。

## 可重定向反编译（历史名称 RetDec）

原覆盖为 x86、ARM、MIPS、PowerPC、PIC32，可产生 C 近似表示和反汇编，也可聚焦一个地址范围。局部函数的编译性、间接调用和环境依赖仍需验证；安装和在线入口不属于知识页。

## 自定义 VM 提升为 LLVM IR（Google CTF 2017）

字节码、opcode 语义、自定义反汇编和 IR 节点之间应存在明确映射。例如 INC 对应整数加一，CDEC 对应条件递减，CALL 对应虚拟调用；虚拟寄存器位宽和状态更新次序不能丢失。内联、常量折叠和死代码消除能减少解释器结构的噪声。

原案例有 26 个寄存器、3 类 opcode，约 1300 行 IL 简化为约 150 行，最终暴露 Collatz 类序列算法。行数减少只是可读性指标，语义等价还需检查状态与输出。

## 精细状态观察（原资料 Advanced GDB）

### 比较事件记录

memcmp 类事件包含两方缓冲区、长度、调用位置、寄存器与 ABI、命中次数。原例读取 rdi/rsi/rdx 适用于其 x86-64 ABI 语境，不是所有平台参数约定。记录后继续与暂停观察可能影响时间行为。

### 逐位置候选

原脚本以已知前缀、当前字符与尾部填充值构造候选，观察成功或失败地址。成立条件是各位置关系明确且每次初态一致；若验证不是前缀渐进，逐字贪心无法代表完整约束。

### 条件位置

寄存器等于给定值、指针内容匹配或第 N 次命中都能定义观察条件。原例跳过前 99 次后观察第 100 次，说明循环中时点的重要性；这些数值不是固定规则。

### 数据访问事件

写、读、读写三种 watchpoint 对应不同依赖。变量名依赖符号，原始地址依赖映射；条件值、访问宽度和跨线程来源也需记录。硬件观察资源有限，漏记不代表没有访问。

### 反向状态与 rr

记录/回放中的事件号、前一位置、前一指令与 checkpoint 能解释关键状态何时被改变。对反调试破坏状态的案例，前后状态差异比仅看失败末态更有帮助；回放可用性仍依赖实际记录的事件和环境。

### 统一上下文

原 GDB Dashboard/GEF/pwndbg 对应寄存器、栈、代码、回溯、映射、地址归属、字符串、十六进制、GOT/PLT、堆块和保护属性。源 De Bruijn 模式只是偏移定位概念，此处不保留生成载荷或安装命令。

## 批量静态标注（原资料 Advanced Ghidra）

CPUID 等指令可以把函数归入检测候选，但候选命名应保留不确定性。XOR 常量提取应关联函数、指令位置、操作数位置和立即数宽度；批量比较函数检索应保留 strcmp/memcmp 的调用者、交叉引用和反编译状态。源脚本中的 API 拼写问题不复制到知识页，保留其目标和证据字段。

## 二进制变化与格式关系

### 指令变化（原资料 Binary Ninja）

原 NOP、条件反转、常量返回样例承载的是改变某条检查后路径的语义差异，不是算法恢复的证明。技术记录应保留原位置、指令长度、分支条件、目标与副作用；本页不复制补丁字节或 API 调用。

### ELF/PE/Mach-O 格式（历史名称 LIEF）

节、段、入口、权限和导入重定位之间存在一致性约束。增加区域、改变入口或 PLT/GOT 目标会同时影响加载器与分析表示。记录这些变化及其原因，比只保留修改后的文件更能支持结论。

## 线性约束与 ILP/LP（BackdoorCTF 2017）

位置编码 `input[i]=i` 可帮助识别比较中涉及的输入位置。原例长度 32、每字节可打印 32–126，约束如 `x[3]+x[7]=0xAB`、`x[1]-x[5]=0x0C`；目标是可行整数解，不需要优化目标。

```text
变量：x[0..n-1] 为整数
边界：32 <= x[i] <= 126（仅在目标确有此域时）
关系：收集到的和、差、等式与不等式
结果：可行解、无解，或尚未覆盖的自由度
```

必须区分整数与有限位宽机器运算；发生溢出或符号扩展时，普通线性方程可能不再对应真实检查。PuLP/Gurobi 是历史求解载体，不保留调用代码。

## 位置编码与 ZF（EKOPARTY 2017）

源经验把位置编码输入与比较时 ZF 联系起来。ZF 是 EFLAGS 第 6 位，表示相关运算结果为零；只有已证明的比较和数据来源才能映射到特定输入位置。源文“一次恢复全部 key”依赖案例结构，任意 ZF 事件并不能自动揭示字节。记录指令、操作数、前后 flags 和输入依赖才能检验该假说。

## 仅执行权限与内存映射（BackdoorCTF 2017）

文件没有读取位仍可能被加载执行；文件权限、进程映射权限与进程内观察机制属于不同层次。源例关联 `/proc/self/maps`、映射起止和 `/proc/self/mem`；这些访问的有效性受系统策略和权限影响，不能当作普遍保证。本页只保留权限与映射的知识关系，移除预加载构造器与转储代码。

## 证据与报告

完整报告可列目标身份、架构、保护线索、IR、handler 语义、真实 CFG、差异匹配、约束、模型假设和反例、文件/运行时对应、输入输出验证及剩余未覆盖路径。结构更简单、函数更短或工具报告成功都只是中间现象。
