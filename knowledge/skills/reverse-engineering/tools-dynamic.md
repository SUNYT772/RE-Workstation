# 动态状态、约束与轨迹知识

来源：skills/reverse-engineering/tools-dynamic.md

本页保留动态插桩、符号执行、跨平台状态模型和侧信道案例。历史软件名称用于对应原文主题；安装、附着、启动、注入和工具 API 调用已转写为观察目标，不提供可运行调用代码。

## 动态插桩（原资料 Frida）

### 环境语义

原安装小节所依赖的技术条件是目标架构、进程位宽、运行时接口与采集端语义一致。动态插桩可观察或改变函数执行，但“能看到数据”和“保持原行为”是两个需要分别验证的属性。

### 函数边界

函数入口的参数、返回后的返回值、调用者地址和比较长度能够揭示真实输入输出。strcmp 的两个字符串与返回值可解释一次比较；memcmp 还需长度和二进制缓冲区，不能按零结尾字符串读取。程序启动时已有的初始化与中途取得的状态也可能不同。

### 反调试与时间依赖

原例关注 ptrace 的 PTRACE_TRACEME 请求、IsDebuggerPresent 返回值和 clock_gettime 的 timespec。知识层面应记录请求类型、原返回值、错误码、检测分支和后续状态。timespec 包含 tv_sec 与 tv_nsec，结构宽度和参数位置受 ABI 影响；把两个字段恒置零只是原文干预示例，不能代表保持真实时间语义。

### 内存扫描与字节变化

可读映射的权限、基址、大小和命中字节构成扫描证据。原样例字节 66 6c 61 67 7b 对应 `flag{`，仅是格式线索。指令字节变化的记录需包含模块相对地址、原字节、新字节、长度及受影响分支；本页不保留 NOP 写入代码。

### 函数替换的语义边界

原文把校验函数改为常量成功返回，展示了观察与干预的差别。常量返回只说明被改变后的调用者路径，不能说明原输入真实通过验证。返回类型、参数类型、副作用和错误路径的缺失都可能改变后续行为。

### 指令轨迹与 Stalker

轨迹记录可包含当前线程、PC、调用目标、指令类别和执行顺序。间接调用目标应由实际操作数和状态解释，不能从 PC 处的字节简单当作指针。原文仅追踪 call 的例子说明如何压缩观察范围，不表示其他指令无关。

### 视图整合（历史名称 r2frida）

导入表、已加载模块、strcmp 调用和内存映射可以共享进程、线程、模块基址与时间点。把这些视图关联起来，才能区分“磁盘中的导入”与“运行时实际解析的目标”。

### Android/iOS 运行时

Java 方法层的类、方法、参数、原始返回值与 native 库调用是不同层次的证据。原案例以 MainActivity.checkPassword 为方法入口；替换实现时递归或调用原方法的差别会改变结果。本页保留方法观察知识，移除服务部署、设备命令和附着代码。

### 递归记忆化（hxp CTF 2017）

若同一参数总得到相同结果且不存在相关副作用，重复递归子问题可归并为缓存项。单参数 key 是参数本身，多参数 key 是完整参数元组；若全局状态、时间或内存也参与，单纯参数缓存不成立。返回值与返回位置只是源例的干预机制，不保留寄存器跳转代码。

```text
F(args):
  若 args 在 cache 中：结果为 cache[args]
  否则：按原递归关系计算 value
        cache[args] = value
        结果为 value
```

Fibonacci 型递归可从指数级重复工作变为线性数量的不同子问题；Ackermann 和一般树遍历的复杂度取决于状态空间，不能概括为所有递归都线性。

## 符号执行（原资料 angr）

### 环境与状态构成

原安装小节转为状态组成：代码、库语义、输入流、寄存器、内存、文件与路径条件。自动加载外部库与抽象库函数会改变模型复杂度；缺失语义可能产生假阳性或不可达候选。

### 路径探索

成功/失败可由指令地址、输出字符串或状态谓词定义。find/avoid 是这些判据的历史名称；源例“Correct!”与“Wrong!”只是消息样式。模型解给出能到达所建模成功状态的输入，仍需要真实校验逻辑或独立语义核对。

### 符号输入约束

原例使用 32 个 8 位符号字节、末尾换行、0x20–0x7e 的可打印范围及已知前缀/右大括号。位宽、长度、换行是否被消费、NUL 与 argv/stdin 的不同语义直接影响约束。前缀只能来源于目标证据，不能把案例格式强加给任意对象。

### 函数摘要

printf、sleep、密码或哈希计算可能造成大量路径或状态开销。摘要的技术目的在于保留相关返回值、输出和副作用；把函数全部跳过或固定成功可能改变接受条件。原 SHA-256 例子将符号输入具体化后计算哈希，这会固定一个候选并丢失一般约束关系，应在模型假设中明确。

### 从函数中段建立状态

中段 PC 不会自动补齐之前的栈、全局变量、分配、文件状态和寄存器。输入指针、缓冲区及长度、返回地址、被调用者保存寄存器和已发生副作用需与实际到达该点的状态一致，否则探索可能得到不可实现路径。

### 常见输入与判据

argv 与 stdin 输入的终止、长度和内存布局不同；多成功地址表示任一候选路径，多失败地址表示要排除的路径。输出匹配可避免地址漂移，但同样要排除诱饵消息。仅取一个解、路径长度上限与 DFS/BFS 影响覆盖面，不能被误报为穷尽所有可能性。

### 路径爆炸

深度优先可集中一条路径，广度优先覆盖更广但占用更多状态。未约束内存/寄存器的零填充是额外假设；符号地址访问、循环、重密码与 I/O 都可能扩张状态。重密码、浮点和复杂堆对象通常需要更具体的语义边界与假设记录。

### CFG 恢复

函数集合、main、基本块及前驱边支持结构理解。静态 CFG 不一定覆盖所有间接目标和自修改结果；函数地址、节点与前驱记录应与运行时边相互对照。

## LLVM 调试状态（历史名称 lldb）

### 基本观察

源文覆盖入口与正则函数位置、单步、寄存器、32 字节内存、字符串、函数反汇编，以及已加载模块。Mach-O、Swift、Objective-C 和 iOS 的价值在于平台类型与加载信息；模块列表可揭示 ASLR slide。

### 结构化状态记录

原 Python 示例从 target→process→thread→frame 取得当前参数，并读取最大 256 字节字符串。这个层次说明线程和栈帧属于证据上下文；参数寄存器随 ABI 变化，字符串长度上限不能当作真实长度。

## Windows 动态状态（历史名称 x64dbg）

### 观察能力

32/64 位进程、代码位置、单步进入/跨过、内存模式、硬件位置与条件日志承载不同观察粒度。源码中的快捷键和启动命令已经转为这些目标。

### 日志条件

命中位置、参数表达式、字符串编码、调用次数和继续执行策略决定日志含义；原 32 位栈参数例与 64 位寄存器参数例不能混用。

### GUI 校验与解包

GetWindowTextA、MessageBoxA 的调用可以把界面输入与成功/失败消息关联到业务路径。解包后的 OEP、IAT 重建与伪 C 是不同产物。Scylla、Snowman、xAnalyzer 是原文的历史名称，分别关联导入重建、反编译和参数注释；不规定使用它们。

## OS 层语义恢复（历史名称 Qiling）

### 环境材料

CPU 语义外，还存在系统调用、文件系统、注册表、动态库与 rootfs 语义。rootfs 和目标 OS/架构不匹配可能表现为缺库或接口失败；这与样本自身错误不同。

### 跨平台对象

原资料覆盖 Linux ELF、Windows PE、ARM/MIPS 固件，也提及 RISC-V、macOS、Android 和 UEFI 的适配。文件/设备依赖与 ABI 必须保留，不能把“跨平台”理解为自动完整模拟一切外设。

### 检测分支与环境差异

ptrace 或 IsDebuggerPresent 的返回值、特定检测位置和原错误码决定分支。模拟环境可能没有常见调试器痕迹，但并不保证绕过所有反调试；未实现的系统调用、时间差和设备属性也可能改变行为。

### 多输入与初态

不同候选间的公平比较依赖相同快照、随机种子、文件和全局状态。输出“Correct”需与实际最终成功对应；前缀局部匹配或错误路由可能产生误判。

## 动态符号执行（历史名称 Triton）

已知具体执行轨迹与指定符号输入并存，收集路径约束和数据依赖，再对关键比较点建立模型。源例为 32 字节输入；变量名排序不自动等于输入位置顺序。单路径 DSE 通常降低同时探索的状态数，但覆盖的是当前轨迹及其约束，并非全部路径。详见[高阶方法](tools-advanced.md)。

## 指令计数侧信道（Hackover CTF 2015）

源案例逐字符比较使正确前缀走得更深，执行指令数也更大。movfuscator 把运算扩展为大量 mov，增加静态阅读困难，但比较分支仍可能泄露进展。原资料称某案例正确字符多执行约 1000 条以上，这是样本特性。计数相关性、初始化成本、噪声与相同状态是判断依据，不保留外部进程调用循环。

### 遗传搜索与定向计数（hxp CTF 2017）

多字符相互作用和自修改导致逐位置贪心不稳定时，原例以指令计数为适应度，保留较高分候选并变异。例参数为长度 40、种群 100、保留 20、单字符变异率 0.1、最多 10000 代和 62 字符候选域；它们是经验参数而非固定要求。原资料“约 30 分钟”仅属于该案例。

```text
population = 候选集合
每代：score(candidate) = 相同初态下观察的相关指令计数
      按 score 排序
      保留高分个体，其他位置由其变异后代补足
```

Go 的查表比较可能使总指令数与正确性无关；此时原例关注特定成功分支的到达次数。计数范围从全轨迹缩小到分支事件，前提是该事件确实表达校验进展。

## 仅 opcode 的轨迹重建（0CTF 2016）

地址排序、去重可恢复代码布局；跳转、调用和返回确定基本块边界；原执行顺序揭示分支采取与否。即使没有寄存器和内存值，快速排序分区的分支也可泄露元素大小关系。排序后的静态布局与原时序必须分开保留，不能排序后丢掉动态顺序。

## 时间与随机性固定的语义（EKOPARTY 2017）

若密码状态或 PRNG 由 time、srand、rand 决定，相同时间和种子使重复观察更可比。原例覆盖 time 返回值及可选输出指针的内容；只控制一个随机来源可能仍不确定。知识结论是“确定性可把复杂状态变为可比较映射”，不保留预加载库、编译命令或运行循环。

### memcmp 前缀匹配计数（Blaze CTF 2018）

源示例把比较的反馈改为连续相等前缀长度，而普通 memcmp 只承诺返回负、零或正，未承诺恰为 -1/0/1。前缀长度能揭示哪里首次不同；其与真实接受条件的关系取决于调用者如何解释结果。观察记录包括双方缓冲区、长度、首次差异、调用次数和成功状态，不保留替换库代码。

## 证据与故障线索

完整记录区分原状态、模型假设、观察干预、覆盖路径、候选解与最终验证。常见失败源有 ABI/位宽混用、ASLR 地址错误、错误长度、遗漏初始化、符号具体化、摘要丢副作用、路径截断、计数不相关和随机性未固定。它们都需要保留反例，不能以某个工具“成功运行”代替结论。
