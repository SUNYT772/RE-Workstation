# AI 辅助逆向：语义恢复与验证证据

来源：skills/reverse-engineering/references/ai-assisted-re.md

## 范围与证据性质

主题包括神经反编译、类型与协议恢复、数学方程提取，以及生成结果的可解析性、可编译性和行为等价性。下列项目、年份、性能与费用为原资料记载的历史信息，本次文档转写未联网核验，不代表当前指标或工具推荐。

## 核心研究与能力

### LLM4Decompile

原文将其描述为将汇编映射到源码的开源框架，覆盖 x86、ARM、MIPS，输入为汇编、输出为 C，训练材料为百万级源码—汇编对。技术目标是恢复高层语义，而不是恢复原始变量名或逐字源码；编译选项和目标架构影响对应关系。

### Decaf（原资料标记 2026）

编译器反馈将生成源码的编译诊断和结果差异反馈到语义恢复中。原资料引用 ExeBench Real -O2 的反编译率从 26% 到 83.9%，用于表达反馈循环的价值。这是特定资料、数据集和评价口径下的数值，不应外推为任意样本的成功率。

### Constraint-Guided Multi-Agent

这里的 Multi-Agent 是历史研究名称，其实质为三类验证依据：语法能否解析、源码能否编译、相同输入下行为是否一致。原文列出的 84–97% 可重执行率与每次 0.03–0.05 美元同样属于历史研究记录。三类依据可以由任意合适过程取得，不要求固定 agent 数量、角色或阶段。

### REMEND

主题是从二进制恢复数学方程。原文记录跨 3 ISA、3 个优化级别和 2 种语言的 89.8–92.4% 准确率，0.132 秒/函数及 12M 参数。保留这些条件有助于理解指标适用范围；公式正确性仍取决于目标位宽、溢出、分支和浮点语义。

### Glaurung

原资料描述为 Rust 内核、Python 绑定的分析体系，包含 ELF/PE/Mach-O、x86/ARM/RISC-V、IOC 与熵分析，并以 plain、rich、JSON、JSONL 表示证据。对知识组织有意义的是结构化证据能区分观察、推断和引用位置，而不是“AI 原生”标签本身。

## AI 增强分析的材料与产出

### 侦察与语义分类

字符串可以按 URL、路径、密钥相关标识、协议片段和错误消息归类；导入表中的加密、网络与文件 API 可支持功能假说，例如 OpenSSL 或 libcurl 家族线索。反汇编中的密码常量、反调试和 VM 检测形态也可辅助分类。`Invalid license` 一类错误消息可关联授权逻辑的位置，但需要交叉引用证明。

### 神经反编译

汇编到 C 的生成结果需要保留函数输入、输出、调用约定、内存副作用、循环和分支。重新编译的结果与原实现进行输出或状态对照，能够检验行为假说。编译成功不等同于语义正确，二进制字节不同也不自动意味着行为不同。

### 多类验证依据

| 依据 | 观察项 | 失败能够说明什么 |
|---|---|---|
| 语法 | 解析树、未定义标识符、类型表达式 | 生成文本尚非有效源码 |
| 编译 | 错误、警告、ABI 与目标选项 | 类型、调用或目标约束存在不一致 |
| 行为 | 同输入下输出、返回值和副作用 | 当前语义恢复与原实现存在差异 |

错误和差异本身应保留为反馈证据，修订的依据是已观察到的不一致，而不是固定次数的重试流程。

### 静态语义恢复

函数重命名应有输入输出或调用点依据；结构体和类定义应关联字段偏移与用途；算法识别应关联轮数、密钥调度、常量与数据布局；协议推断应关联包序列和字段变化；中文或英文注释可表达推理，但应区分直接事实与假设。

### macOS/iOS 私有框架与 MOTIF

私有框架缺少文档、类型信息时，方法使用模式和调用上下文可以支持参数类型与签名假说。原文引用 ObjC 签名恢复率从 15% 到 86% 的对比，未提供本次可复核实验；保留为原文历史研究声明，而非保证。

## 语义分析记录结构

### 函数语义

原提示模板转为报告字段：功能概述、候选语义名称、输入参数及可能类型、返回值、外部 API/函数依赖，以及密码、认证、网络、文件 I/O 等相关行为。每个字段都可以记录位置、支持证据和不确定性，不保留角色扮演或强制提示语。

### 算法识别

记录候选算法（AES、DES、RC4、TEA、ChaCha20 或自定义）、轮结构、密钥调度、密钥大小和常量证据。常量匹配只是线索；实际的数据流与轮函数决定识别可信度。

### 协议格式

记录 magic、长度、包头结构候选、校验和/CRC 候选字段，以及已有协议或自定义协议的判断。字段的宽度、端序、随载荷变化关系和多个包之间的一致性能够支持或否定结构假说。

## 方法适配与局限

快速源码草案、高精度语义验证、数学函数提取、跨格式证据归并和交互式注释分别对应不同目标。原文列出的本地 GPU、免费开源和单次 API 成本仅是历史资源背景，不构成依赖、预算或调用要求。

复杂虚拟化/平坦化、VMProtect、间接调用、虚表、函数指针、内联边界和向量浮点运算都可能导致恢复错误。大函数（原文以超过 1000 行为例）也可能超过上下文容量。有效知识记录应保留未决调用、位宽、路径、浮点差异和上下文缺口，不能用流畅注释掩盖未知项。
