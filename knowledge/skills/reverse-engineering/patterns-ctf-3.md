## 单行 Python 布尔电路（BearCatCTF 2026 Captain Morgan）

### 表示与识别

样例以超过 2000 个分号分隔语句，使用 `:=` 海象运算符串联赋值，把 29 字节输入按大端解释为一个整数，再以移位和位运算构成校验电路。`__builtins__` 访问、`ord`/`chr` 与输入转换的联系，是识别输入进入电路的线索。

### 等价关系

`(a|b)&~(a&b)` 与逐位 XOR 等价，赋值链可以拆成依赖图；终结条件是特定结果变量等于零。29 字节对应 232 个输入位，但 Python 的整数没有固定位宽，位取反和右移的语义也不自动等于固定宽度无符号位向量。模型需明确掩码、输入非负性与逻辑右移条件，不能仅替换运算符名字。

### 结果与局限

结果包括输入端序、每条赋值依赖、最终谓词、字符限制以及候选的电路复算。原资料“不到一秒”是该实例的历史经验，不构成复杂度保证。保留 Z3 作为原约束表达背景，不复制求解器调用代码。

## 滑窗 popcount 的差分传播（BearCatCTF 2026 Treasure Hunt 4）

### 观察与递推

每个长度为 16 的比特窗口都有期望汉明重量。窗口向后移动一位时，只移出一位并移入一位，因此：

```text
count[i+1] - count[i] = bit[i+16] - bit[i]
bit[i+16] = bit[i] + count[i+1] - count[i]
```

原样例有 337 个计数，对应 `337+15=352` 位。数组值应在 0–16，长度关系和取位方向都可独立核对。

### 自由度与筛选

仅首个 16 位窗口自由，最多 65536 种；还须满足首项 popcount。可行首窗数量为组合数 `C(16,count[0])`，不是固定 4000–8000。之后每一位由递推唯一决定，若得到 0、1 以外的值立即说明该首窗不成立。

### 结果表达

原记录按 MSB 优先恢复字节。已知前缀或可打印性只能辅助选择，不能代替全部窗口复核；可能存在多个完整满足的序列。报告需给出位序、首窗、各轮计数与候选数量。

## 系统调用副作用与相邻内存（Hack.lu 2015）

### 结构与边界

`rt_sigprocmask` 的输出指针接收旧信号集合，它会写内存，并非只返回状态。原输入解析路径把某些字符映射为带此副作用的调用。原记录提到字符区间 `0x3A–0x40`、四字节输入区 `0x603390`、相邻安全变量 `0x603394` 和输出指针 `0x603397`。

## VM 的顺序密钥链（Midnight Flag 2026 67）

### 识别与依赖

字节码 opcode 经过统一 XOR 编码后可能呈现 ASCII 外观，重复字节码与 CHECK 常量构成分块校验。原案例每块 3 字节，候选域 `2^24`，共约 287 块；上一块输出状态作为下一块输入，因此块间依赖有序，块内候选则相互独立。

### 原运算关系

```text
saved = input_val XOR old_key
val = saved
重复 1000 次，状态为 32 位：
  val = val XOR (val << 13)
  val = val XOR (val >> 17)
  val = val XOR (val << 5)
  val = val * 0x2545f491
判定：val XOR saved == expected_next_key
```

各步按原无符号 32 位截断，右移为逻辑右移，块的字节拼接次序要保持。常量是变换参数，具体密钥链值不保留。

### 判断与结果

迭代多不意味着数学上必然不可逆；原资料把其描述为难以解析反转的 hash 类变换，这是案例策略选择。结果需注明每块初态、CHECK 目标来源、候选碰撞与传递关系。原 OpenMP 并行实现、编译指令及固定并发要求已移除。

## GLSL 自修改纹理 VM（ApoorvCTF 2026 Draw Me）

### 内存布局与指令集

程序存储在 256×256 RGBA 纹理中，像素既可表示指令又可作为输出。原布局如下：

| 位置 | 内容 |
|---|---|
| 第 0 行，像素 0 | 指令指针 |
| 第 0 行，像素 1–32 | 通用寄存器 |
| 第 1–127 行 | 程序存储，RGBA=`opcode,arg1,arg2,arg3` |
| 第 128–255 行 | VRAM |

原 opcode 对照为 0 NOP、1 SET、2 ADD、3 SUB、4 XOR、5 JMP、6 JNZ、7 VRAM-write、8 STORE、9 LOAD，每帧解释 16 步。操作数是否寄存器或立即数必须从 handler 确认，名称本身不足以完整定义语义。

### 自修改与可见结果

第一部分以 STORE 修改后续绘图代码，尤其是 SET 中的像素颜色；第二部分读取修改后的指令并写 VRAM。STORE 目标坐标来自寄存器，写入值由一组相邻寄存器组成，覆盖的是整像素四通道。原图像文件本身就是字节码，不是附带插图。

### 并行冲突的定位

原 shader 对每像素每帧仅保留一个写目标，多次写会使只有最后一次留下；原记录称超过 75% 的像素丢失，这是该实现的现象。GPU 并行并不必然导致此问题，原因在状态提交与写冲突的具体表达。STORE 解码与 VRAM 绘图都需要说明读旧纹理还是本轮已改状态。

### 顺序语义与结果

知识上的参照模型是按原指令顺序提交每次 STORE 和 VRAM 写入，比较其与每帧并行模型的差异。结果保留解码前后程序像素、指令指针、寄存器、VRAM 写序和最终图像。原模拟代码只展开部分 opcode，不是完整解释器；本页不复制其运行框架。

## 线程竞态与有符号扩展（Codegate 2017 Hunting）

### 故障结构

### 证据表达

## 16 位 MBR 与 psadbw 约束（CSAW 2017）

### 指令语义

启动扇区处于 16 位代码背景，但校验使用 SSE2 `psadbw`。128 位形式分别对两个 8 字节组求无符号字节绝对差之和，两个组的结果分别落在相应 64 位分区的低位，并非将全部 16 字节合成单一和。

### 约束形式

每组可表达为 `Σ|a[i]-k[i]|=C`。原样例通过掩码使每次仅有两个未知输入字节；其余字节的固定贡献也必须计入。可打印域 0x20–0x7e 共 95 个值，双字节约 `95²` 候选；源示例的半开区间写法可能漏掉上界，应区别数学域与程序枚举。

### 结果表达

记录掩码、已知贡献、两个分组、比较宽度和多解。字符格式与后续迭代可筛选候选，不能只凭一组绝对差等式保证唯一。原调用求解库的代码不保留。

## DNN 的逐层逆关系（N1CTF 2018）

### 原模型

原二进制实现五层 sigmoid 网络，输入字符先作 `1.0/char_value` 变换。权重与偏置可能以浮点常量数组存在，矩阵乘法和 sigmoid/tanh 的调用是识别线索。

### 数学关系

sigmoid 为 `σ(z)=1/(1+exp(-z))`，在 `0<y<1` 时逆关系为 `log(y/(1-y))`。若正向采用行向量 `y=σ(xW+b)`，则逆关系是 `x=(logit(y)-b)W⁻¹`；若采用列向量，乘法方向需相应调整。按输出层到输入层逆序应用，再反转输入倒数关系。

### 条件与误差

方阵不自动可逆，必须满秩；浮点饱和到 0/1 时 logit 不再有限，病态矩阵会放大误差。取倒数、舍入成字符只是候选构造，需回代全部层并核对原比较容差。原资料“方阵表示可逆”的简化在此标明，不复制矩阵库调用。

## BPF 到本机 JIT 的对照（Midnight Sun 2018）

### 结构识别

原二进制创建原始套接字并通过 `SO_ATTACH_FILTER` 附着过滤器，`sock_fprog` 描述长度与程序指针。经典 BPF 的 `sock_filter` 单项 8 字节，字段为 `code`、`jt`、`jf`、`k`；分支偏移与立即数含义由 opcode 决定，不能按任意本机指令解释。

### 字节码与本机语义

原资料利用内核 BPF JIT 的本机 x64 输出作为另一种表示，观察包字段加载、比较、分支和返回值。JIT 日志与可见形式依赖内核版本、权限和配置，不能保证从日志获得完整本机代码，也不能把当前 eBPF 与经典 BPF 的表示混同。

### 结果表达

原分析推断过滤条件涉及 UDP 3333 端口与 DNS TXT 请求；这是包格式条件，不包含外部查询或挑战输入。报告应对应字节码条目、本机基本块、字段偏移、端序和接受/丢弃结果。本页不包含内核开关修改、运行样本或网络请求命令。
