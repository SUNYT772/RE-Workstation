# .NET 托管分析框架

来源：skills/dotnet-reverse/SKILL.md

## 适用范围与概念

覆盖托管 PE、C# EXE/DLL、Mono/Unity 托管层、Xamarin/MAUI 的 C# 层、Sharp 系列程序、混淆程序集以及 loader、info-stealer、RAT 中的托管配置和通信逻辑。验证判断、常量和 IL 差异属于代码语义问题。纯 C/C++/Go/Rust 本机程序、NativeAOT 与 IL2CPP 的本机产物具有不同的分析模型。

原六阶段工作流在此转为六个相互关联的知识面：格式识别、混淆机制、恢复后的内容、静态结构、运行时值、修改语义；它们不构成固定 agent 顺序。

## 核心原理与技术细节

### 识别 .NET

典型标志包括 PE `Data Directory[14]` 的 CLR Runtime Header 非零，`mscoree.dll` 与 `_CorExeMain`，metadata 流 `#~`、`#Strings`、`#US`、`#GUID`、`#Blob`，以及 `mscorlib` 或 `System.Private.CoreLib`。普通 PE32 标识不足以证明是托管程序集，能够被某个界面打开也不代替格式证据。

NativeAOT 可能没有 CLR 头，但仍留有 `System.Private.CoreLib` 字符串与重构过的类型元数据；单个字符串因此不能把它归为标准 IL 程序。IL2CPP 将 Unity 托管逻辑转成本机代码；其 C# 来源不意味着产物仍有可直接阅读的标准托管方法体。

### IL 与 C# 的信息层次

C# 反编译视图适合类、签名、字符串和高层结构的定位；IL 更接近真实方法体和控制流。async/await、yield、闭包与编译器状态机可能在高层重构中失真。重要判断、加密循环与方法修改的解释需要对应具体 IL，而不是只依赖美化后的 C#。

### 混淆器与恢复对象

| 混淆器 | 原材料保留的特征 | 需要理解的恢复对象 |
| --- | --- | --- |
| ConfuserEx 1.x/2.x | 模块 anti-tamper、控制流变形、字符串加密 | 方法完整性、明文字符串和分派状态 |
| SmartAssembly | circular/string encoding、资源压缩 | 字符串编码与压缩资源 |
| Babel.NET | 方法体加密、控制流 | 方法体与真实控制流 |
| Eazfuscator.NET | 字符串、资源加密 | 解密器与资源语义 |
| .NET Reactor | anti-tamper、necrobit | 运行时方法体和 metadata |

原 de4dot 类型名 cfze/sa 等是历史识别标签。自动识别失败、unknown 或恢复产物打不开，可能是私改、多层保护、版本差异或完整性检查，不能简单归因于文件损坏。恢复目标可以是仅理解字符串，也可以是结构重建，不必把所有保护都作为同一问题。

### 静态结构与入口

Main、Startup 与 Module `.cctor` 是不同初始化层次。flag/password/verify/check/encrypt/http/Config 等词属于定位线索；字符串的反向引用将文本关联到方法，再由 IL 判断实际条件。类名可读程度不是语义恢复成功的充分证据。

### 运行时观察

解密后的字符串、C2 地址、配置对象、参数、返回值和异常路径可以补足静态缺口。原材料提到托管调试可直接展示对象字段与字符串；其技术价值是观察真实值，而非要求某个调试器。try/catch 可能承载正常控制流，异常发生并不等于错误路径。

### 按需修改的语义

布尔值加载、数字/字符串常量、条件分支、返回和空操作是原修改类别。C# 重编译涉及引用与重新生成 IL；逐指令 IL 修改更容易保留未改区域的原始结构，但原“几乎不会失真”属于相对经验，不等于可忽略栈和异常区域一致性。记录以原/新方法体、预期返回/分支和实际可观察结果为核心，不保留绕过指令配方。

### 历史能力分类

原工具映射对应六种能力：反编译/调试/修改、批量或无界面反编译、脱混淆、保护识别、metadata/IL 编程表示、结构化分析接口。dnSpyEx、ILSpy、de4dot、DIE、dnlib、dnSpy MCP 是原实现名称；它们不被列为必需依赖。平台许可、allowed-tools、自动触发和注册元数据不进入知识页。

## 观察项与判断依据

托管身份依据来自 CLR 头与 metadata，混淆类别依据来自方法体、资源和初始化器，逻辑结论依据来自 IL、引用和运行时值。Sharp 系列程序的行为要落到分派方法、P/Invoke 和协议数据；程序名称不是行为证明。

## 故障定位与经验

乱码类名、满屏状态分派与加密资源表示可读性受保护，不等于所有逻辑不可解释。C# 无法重编译可能来自缺引用、lambda/状态机重构问题；运行时正常而离线方法体空缺可能与方法加密相关。混合本机 loader 与托管内容可以分别解释两层，避免让一个格式假设覆盖所有对象。

## 证据与报告结构

记录可包含原程序集身份、CLR/metadata 标志、混淆器特征、方法 token、入口与初始化器、关键方法、解密结果的字段类别、C2/配置结构和来源、原/恢复/修改版本关系、IL 对照以及未验证假设。实际密钥、令牌和证书私密材料不随知识副本保留。
