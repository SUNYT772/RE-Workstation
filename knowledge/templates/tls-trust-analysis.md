# TLS 信任与证书固定

## 输入与上下文

连接目标、证书链、主机名、网络栈、系统/应用信任策略。

## 方法与判断

原模板区分 OkHttp CertificatePinner、链清洗、TrustManager/checkServerTrusted、WebView SSL错误、HostnameVerifier 和 Cronet；注释虽提及 BoringSSL，具体实现覆盖需与 Native 证据对照。链可信、主机名一致、证书固定、WebView错误处置是独立层次，不应混为一个开关。

## 原模板实际返回契约与覆盖

| 对象或回调 | 输入与实际返回形态 | 覆盖与判断边界 |
| --- | --- | --- |
| OkHttp CertificatePinner.check | 输入包括主机名与对端证书列表；原片段为空返回 | 空返回不是证书链对象，也不是布尔通过值；该片段未运行原检查，日志文字不等于已经验证整条 TLS 路径。 |
| CertificateChainCleaner.clean | 输入为证书链与主机名；原片段返回传入的原链 | 原链返回与空返回不同，也不证明已经重建或验证到可信锚的完整链。 |
| TrustManagerImpl.verifyChain | 输入含待验证链、信任锚链、主机及认证上下文；原片段继续进入原验证过程，但未显式返回其结果 | 不能把它描述为已将原链或原验证返回值透传；缺少显式返回对调用方的影响需要结合真实方法签名判断。 |
| X509/TrustManager 的 checkServerTrusted | 原片段枚举类名同时含 TrustManager 与 X509 的已加载类，并为相应重载提供没有显式返回值的实现 | 对 void 契约与需要对象返回值的重载不能作同一种解释；声明了枚举逻辑不等于覆盖所有运行时实现。 |
| WebView SSL 错误回调 | 输入含 WebView、错误处理器与错误对象；原片段作继续加载的处置，没有显式返回值 | 这是错误处置动作，与返回布尔值或证书链不同；不证明其他网络栈的校验行为已经改变。 |
| HostnameVerifier.verify | 输入为主机名与会话；原片段明确返回布尔真 | 原模板将该验证器设为默认 HostnameVerifier；默认验证器的作用域不能扩展成所有 HTTP 客户端或 Native 栈的共同结论。 |
| Cronet | 仅检测 CronetUrlRequestContext 类是否存在并输出检测提示 | 没有在该片段中实现 Cronet 专有校验逻辑或提供其返回契约；日志中将其归于 TrustManager 不足以证明覆盖。 |
| BoringSSL | 仅在原注释的覆盖列表中出现 | 未给出相应 Native 实现；不能从标题或注释推断已经处理该栈。 |

空返回、没有显式返回、返回原链与返回布尔真分别保留其含义，不能统一标作“校验成功”。原模板多处捕获异常但未记录细节，类不存在、方法或重载不匹配与实际命中属于不同状态；启用提示或检测到类均不能代替连接结果及对应层次的证据。

## 建议的结果结构

失败所在层、类与方法、证书链/主机名的脱敏描述、策略差异、原始与对照结果，以及实际返回形态与覆盖状态。这些是建议的报告字段；原模板多为状态日志，没有自动收集完整证书链、原始与对照连接结果或全部校验层的结论。
